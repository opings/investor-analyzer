# guru-view

基于已沉淀的大V资料，对给定标的输出**视角点评**，而不是凭空发表观点。

按问题里涉及**几位大V**自动分流：

- **单人模式**（1 位）→ 风格契合度评估
- **多人模式**（≥2 位，或"大V们/谁看多谁看空"）→ 观点对比矩阵

两种模式的检索逻辑相同（都读 `current-view.md` → `posts/`/`calls/` → `coverage.md`），只是输出格式不同。

## 何时激活

**单人**：
- "用 XX 视角看 600519"
- "如果是 XX 会怎么评价腾讯"
- "XX 对白酒板块怎么看"

**多人**：
- "对比 A 和 B 对 600519 的看法"
- "大V们怎么看 AI 算力 / 港股 / 红利策略"
- "谁看多腾讯，谁看空"

> 单一大V且已有专属 skill（如老唐 → `tangchao`）时，深度查询优先走专属 skill；本 skill 负责通用的跨 guru / 无专属 skill 的视角点评。

---

## 通用前置（两种模式都先做）

0. **先读 `knowledge/gurus/INDEX.md` 花名册**（一切的第一步）
   - 把用户输入的中文名/别名映射到目录 slug（如 巴菲特→`warren-buffett`）；花名册里查不到的大V → 该目录不存在，直接告知用户"未收录"，**不要臆造目录**
   - 看该大V的**状态列**：`⚪ 骨架` 表示只有模板占位（`收录文章数: 0`）→ **先声明"该大V知识库尚未录入，无法基于已沉淀观点点评"**，不要拿模板/训练数据硬答；多人对比时只纳入 `✓ 已沉淀` 的，骨架大V单列一句"待录入"
1. **确认数据是否充足**
   - **先读 `knowledge/gurus/<昵称>/current-view.md`**（当前有效立场快照）——打分/取观点的首选，不要直接读几百行的 `style.md`
   - 没有 `current-view.md` → 退回读 `style.md` 最新一年的节
   - 都没填 → 提示用户先用 `ingest-guru` 喂几篇数据
2. **查覆盖率，防止拿空洞硬答**
   - 读 `knowledge/gurus/<昵称>/coverage.md`，确认相关时段非 ✗
   - 落在空洞 → **先声明**"该大V这段时间无数据"，再说明只能基于其它时段的稳定立场推测
3. **到 `posts/`/`calls/` 搜该标的代码 / 中文名 / 相关主题**，取具体表态（带日期 + 文件路径）

## 单人模式：风格契合度评估

### 三层信息分级输出

- **第一层 · 直接观点**：该大V在 `posts/`/`calls/` 里**明确说过**这个标的的话，原文摘录 + 日期
- **第二层 · 同行业类比**：该大V对**同行业其他标的**说过什么，可类比但要标"类比推测"
- **第三层 · 风格契合度**：用 `current-view.md` 的当前框架打分，比如"这只股票 ROE 15%、PE 30x，按 XX 偏好 ROE>20% 且 PE<20x 的标准，契合度低"
- ⚠️ **注意观点演化**：打分用 current-view 的"最新有效版"，不要用 `style.md` 里已被废弃的旧标准（current-view「已废弃/已演化」表会列出来）

### 输出格式

```markdown
# <大V昵称> 视角：<标的名称 代码>

> 分析日期：YYYY-MM-DD
> 数据基础：N 篇文章 / M 次持仓快照，最近更新 YYYY-MM-DD

## 1. 直接观点（有则列，无则跳过）

- YYYY-MM-DD，<post 文件路径>：「原文摘录…」

## 2. 同行业/同主题类比

- 该大V对同行业 XXX 说过…（日期）
- 该大V持仓里有/没有该行业代表

## 3. 风格契合度

| 维度 | 该大V偏好 | 标的现状 | 契合 |
|------|-----------|----------|------|
| ROE  | >20%      | 15%      | ✗    |
| PE   | <20x      | 30x      | ✗    |
| 行业 | 消费/医药 | 科技     | ?    |

## 4. 结论（保守措辞）

"基于现有数据，<大V>对该标的更可能持<看多/看空/中性>态度，主要因为…。但需注意：<数据局限>。"
```

## 多人模式：观点对比矩阵

### 确定参与方

- 用户指定了哪些大V？没指定就把 `knowledge/gurus/` 下**所有提到过该标的/主题的大V**都拉进来
- 没提过的不要硬塞；近期落在空洞的，归入"数据局限"而非"未表态"
- 逐人提取：日期、方向、核心论据（一句话）、原文路径

### 输出格式

```markdown
# 大V观点对比：<标的/主题>

> 分析日期：YYYY-MM-DD

## 观点矩阵

| 大V | 方向 | 最近表态时间 | 核心论据（一句） | 原文 |
|-----|------|------------|----------------|------|
| A   | 看多 | 2026-04   | 现金流稳健     | posts/2026-04-12-…md |
| B   | 看空 | 2026-03   | 估值过高       | posts/2026-03-08-…md |
| C   | 中性 | 2026-02   | 等回调         | posts/2026-02-19-…md |

## 共识

- 都认可…（列出 2-3 条交集）

## 分歧

- 关于 XXX：A 认为…，B 认为…
- 分歧根源：估值锚 / 行业周期判断 / …

## 时间维度

- 半年前 vs 现在：谁的观点变了，怎么变

## 数据局限

- D、E 在 knowledge/gurus/ 里有目录但近半年没提过该标的，未纳入对比
```

## 注意事项（两种模式通用）

- **不替大V发表新观点**：永远基于已归档的资料，没有就说没有
- **直接引用必须带日期 + 文件路径**，方便用户回溯原文
- **保守措辞**：用"更可能"、"倾向于"，不用"会"、"一定"
- **指出数据空白**：先查 `coverage.md`，落在空洞时段要明说
- **读 current-view 不读 style 全文**：style.md 是演化史（会很长），打分/取观点用 current-view 的收敛快照；只有用户问"最初/历史上怎么看"才翻 style.md 对应年份
- **方向标签统一**：看多 / 看空 / 中性 / 已平仓 / 未表态
- **避免平均化**（多人模式）：不要为对称凑数，3 个看多 1 个看空就如实写
- **时间敏感**：半年前的看多 ≠ 现在还看多，每条观点标时间

## 关联

- `ingest-guru` / `ingest-book`：本 skill 读取的数据来源
- `backtest-call`：把"观点"接受行情检验（本 skill 给立场，backtest 给胜率）
