# ingest-book · Phase 3：Skill 打包（一个 guru 累积 ≥3 年笔记后，30 分钟）

把厚度足够的 guru 知识库打包成专属查询 skill（如 `tangchao`）。这是元任务，整个 guru 生命周期只做一次（之后增量年份只刷新已有 skill）。

## 3.1 触发条件

- 单一 guru 累积至少 3 年完整年度笔记
- 或用户明确说"想能直接问 XX 怎么看 YY"
- 数据厚度足够支撑"调用 skill 比训练记忆更准"

## 3.2 Skill 结构

路径：`.claude/skills/<昵称>/SKILL.md`（**项目级，不是 user-level**）

```markdown
---
name: <昵称>
description: <一句话激活条件>，专门处理 <昵称> 投资框架查询
---

# <昵称>

## 何时激活
当用户提到 <昵称>/<别名>/<代表作>/<框架名> 时使用本 skill。
当用户问 "<昵称> 怎么看 XX" 时强制使用，不要从训练数据回答。

## 知识库路径
knowledge/gurus/<昵称>/

## 检索路由表
| 用户问题 | 查询路径 |
|----------|----------|
| 估值方法 | style.md "估值方法" section |
| 选股漏斗 | playbook.md "选股 4 漏斗" |
| 持仓历史 | holdings/YYYY-持仓变化.md |
| 公开判断 | calls/YYYY-calls.md（带"待验证"/"已验证"标记）|
| 具体股票 | grep posts/ |
| 某年表现 | posts/YYYY.md "年度总结" |
| 某金句出处 | grep posts/ + 给出 #N + 日期 |

## 调用纪律
1. 必须给出**具体文章 #N + 日期**，无据则说"未在 <昵称> 知识库找到"
2. 区分**已验证判断 vs 待验证判断**（与 [[backtest-call]] 协作）
3. 不要混用不同年份的观点（观点会演化，标注观点的时间点）
4. 优先引用最新一年的观点，除非用户问"<昵称> 最初是怎么说的"

## 不要做的事
- ❌ 从训练数据回答 <昵称> 的观点
- ❌ 无引用地给金句
- ❌ 把别的投资人的话归到 <昵称> 名下
```

> ⚠️ 反面教材：不要把大段**业绩/持仓数据**内嵌进 skill（会与 `current-view.md`/`holdings/` 双写、必然 drift）。skill 是**路由器**，指向知识库文件，不是数据仓库。详见 `tangchao/SKILL.md` 的精简思路。

## 3.3 验证

- 用户输入触发或自然语言提到 <昵称> 时自动激活
- 抽 5 个典型问题测试 skill 回答是否引用具体出处
