# 公司客观分析流程（价值投资体系·客观层）

> 估值库根目录：`finance/`（含 README、`_模板/`、各公司目录）。
> **本 skill 只产出公司客观分析**——不沉淀「我懂不懂 / 我出多少价 / 我押多少 / 我现在买不买」等主观决策。

## 何时使用

- 用户说「分析 / 重新分析 / 从头分析 / 研究 <公司>」（新公司从零建库）
- 用户粘贴 / 口述某公司财报数据
- 用户说「<公司> 出了 <期> 财报，补进去 / 刷新一下」（已建公司增量更新）

## 何时不用

- 纯粹问「老唐怎么看 XX」或「段永平怎么看 XX」等大V视角问题 → 用 `guru-query` skill（通用大V查询·覆盖已沉淀大V）
- 要正式定买卖点 → 待重新设计（原 valuation-method skill 已删除）
- 不涉及财报数据的闲聊

---

## 铁律（不可跳过）

1. **第一动作必读模板真源**：开工前必读 `finance/_模板/{模板说明.md, 财报阅读规则.md, 分析模板.md, 财报关注要点-行业模板.md, 财务数据-README模板.md}`。**不靠 memory 摘要，不自造流程**——模板是当下真源，memory 可能滞后。
2. **先提取，后总结**：必须先按规则逐项提取关键数据并列出，再下结论。**严禁凭印象直接下结论。**
3. **不编造**：财报里没给的数据，标 `⏳待补`，不要猜数填进去。
4. **数字一律落 `财务数据/<csv>`**，分析层 `.md` 不复制数字、只做概括引用。三表勾稽校验不过不写出 CSV。
5. **不沉淀主观决策**：估值方法选择 / 合理 PE / 买卖点 / 能力圈 / 仓位 / 操作 全部不在 `finance/<公司>/` 下沉淀。
6. **单一真相**：通用红旗以 `knowledge/造假案例库/造假模式库.md` 为准、三大前提取数流程在 `财报阅读规则.md`；本 skill 只按序执行、不重抄。**估值公式/双闸门 canonical 已删除·待重新设计**。

## 执行流程

### Step −1：事实底座前置门槛（缺则先补，再分析）

> 见规则 `财报阅读规则.md` 的「Step −1」。分析前**必须确认三样到位，缺任一样先补齐再走**（残缺底座不准出分析结论）。
>
> **🚨 硬 gate（不许口头带过）：进入 Step 0 之前必须显式输出以下「底座盘点表」，逐格打钩；表内任一 ❌ 立即停下补，绝不进入 Step 0。**

#### 底座盘点表（必填·任一 ❌ 硬停）

| 类别 | 应有内容 | 命名规范 | 实际状态（`ls report/<公司>/` 等自证） | 打钩 |
|---|---|---|---|---|
| ① 三表 CSV | 覆盖上市至今全部年份 | `finance/<公司>/财务数据/{利润表,资产负债表,现金流量表,财务比率,分部营收}.csv` | | ✅/❌ |
| ② 事实编年 | 近 3 年 | `knowledge/companies/<公司>/YYYY-MM.md` | | ✅/❌ |
| ③a **招股说明书** | IPO 发行文件（独家含上市前 3 年经审计数据） | `report/<公司>/招股说明书.pdf`（补充 → `-YYYY-MM补充.pdf`） | | ✅/❌ |
| ③b **上市至今全部年报** | 一份都不能少 | `report/<公司>/YYYY.pdf`（每年一份） | | ✅/❌ |
| ③c **中报** | 上市至今每年一份 | `report/<公司>/YYYY-H1.pdf` | | ✅/❌ |
| ③d **季报**（A 股必备/港股按披露） | 上市至今每期一份 | `report/<公司>/YYYY-Q1.pdf` `YYYY-Q3.pdf` | | ✅/❌ |

> **"6 份年报 = 底座到位"是错觉** —— 招股书 + 中报 + 季报同样是硬项。**"这就是全部可得"不是理由**——需先跑 `scripts/notices.py` 或港交所披露易/巨潮实证不可得，才能标 🟢；未查证就默认 ❌。
> 缺件下载法（A股/港股均走巨潮 cninfo）：`python3 scripts/notices.py <发布窗口起> <止> <代码>` 探 announcementId → `curl -fsSL http://static.cninfo.com.cn/finalpage/{公告日期}/{id}.PDF` → `file` + 大小 MB 级 + 首页三验。

#### 三样详情

1. **上市至今三表 CSV（从 ③ 一手财报 PDF 解析·唯一真源）** → `finance/<公司>/财务数据/*.csv`，逐行解析 ③ 财报 + **勾稽自洽校验** + 比率派生（ROE/现金含量/capex/毛利率，`_build_from_pdf.py`）；**不用东财二手**（`fetch_fundamentals.py`/`_raw_akshare` 已弃用，二手会错：农夫 256→211 现金流坑）。
   - **起点 = 招股书披露的上市前最早年份**（招股书含 IPO 前 3 年财务数据）；**终点 = 最新一份定期报告**。缺招股书 = 缺上市前 3 年真源。
2. **近 3 年事实编年** → `knowledge/companies/<公司>/YYYY-MM.md`；没有就先补一手公告/事件。
3. **一手财报 PDF 全集** → `report/<公司>/`：**招股书 + 上市至今全部年报 + 中报 + 季报，一份都不能少**（见上表 ③a-③d）。
   - **为什么每一类都必须有**：招股书 = 上市前 3 年唯一真源；年报 = 全部披露 + 附注；中报/季报 = 最新经营动向的一手来源（年报有 3-6 个月滞后，只用年报 = 用过期底座估当下）。

**新公司从零建库 vs 已建公司增量更新**：
- 从零建库 → 三样从头建（PDF 全集下载：招股书 + 全部年报 + 全部中报 + 全部季报、三表全解析、编年补 3 年）
- 增量更新 → 加最新一期 PDF（年报 / 中报 / 季报）+ 解析新一期三表 + 编年补最新事件

### Step 0：读模板（每次必读，按顺序）

1. `finance/_模板/模板说明.md` —— 三件套结构 + 数据流 + 真源原则
2. `finance/_模板/财报阅读规则.md` —— 通用 SOP（生意类型判断 / 数据取数 / 三大前提 / 排雷 / 输出纪律）
3. `finance/_模板/分析模板.md` —— `分析.md` 标准结构
4. `finance/_模板/财报关注要点-行业模板.md` —— 行业块（白酒/银行/周期/平台/医药/制造），新公司套最近行业起步
5. `finance/_模板/财务数据-README模板.md` —— 财务数据/README.md 标准结构
6. `finance/<公司>/财报关注要点.md` —— 该公司特有看点（已建公司）。**若不存在 → 本次必须新建**（从行业模板起步，沉淀生意模式/护城河本质 + 核心跟踪变量 + 独有红旗）。

### Step 1：判断生意类型（公司客观属性·不是估值方法选择）

按规则 Step 0 三选一：
- **成长稳定**（利润稳定增长，茅台/腾讯/古井/农夫等）
- **强周期**（利润随商品价格/景气大起大落，陕煤/中海油/分众/胜狮等）
- **不确定生意**（爆款依赖/IP 周期短/技术路线未定/缺乏稳定盈利）

> 📐 本 skill 只判生意类型（公司客观属性），不做估值方法选择/估值动作（那是下游主观决策·待重新设计）。

### Step 2：按清单提取并列出「关键数据」

> **🚨 硬 gate**：本步骤**必须显式输出「关键数据提取清单表」**（四类逐项 + 落点 + 值/⏳待补），才能进入 Step 3。"我已经取了数"这种口头带过 = 违规。缺失项标 `⏳待补`，不猜数。

对照规则 Step 1-3 + 公司关注要点 + 行业模板特有指标，逐项提取并**显式列出**：

- **核心财务数据**（→ `财务数据/利润表.csv` / `分部营收.csv`）：扣非归母净利+营收+增速、分部/区域/产品收入、次年经营计划
- **三大前提验证数据**（→ `财务数据/财务比率.csv` 派生）：经营现金流/净利、合同负债、应收账款、销售收现÷营收（直接法）或合约负债+应收周转（间接法）、资本开支/净利、毛利率、ROE、三费率
- **三表勾稽补充取数**（规则 Step 2④，供 3.0 勾稽用）：货币资金、净资产、利息收入、预付/其他应收/其他流动资产
- **公司/行业特有数据**：从年报 MD&A 或附注取（如白酒看基酒/经销商/批价、银行看不良率、消费品看分部利润率、重资产看 PPE 明细附注 14 - 在建工程是模板列出的「藏雷点」必查）→ 落 `财务数据/<主题>.csv`

#### 关键数据提取清单表（必输出·四类逐项打钩）

| 类别 | 具体项 | 值（最近一期） | 落点 | 状态 |
|---|---|---|---|---|
| 核心 | 扣非归母净利 + 增速 | | `财务数据/利润表.csv` | ✅/⏳ |
| 核心 | 营收 + 增速 | | `财务数据/利润表.csv` | ✅/⏳ |
| 核心 | 分部/区域/产品收入 | | `财务数据/分部营收.csv` | ✅/⏳ |
| 前提① | 经营现金流/净利 | | `财务数据/财务比率.csv` | ✅/⏳ |
| 前提① | 合同负债 + 应收账款 | | `财务数据/资产负债表.csv` | ✅/⏳ |
| 前提② | 资本开支/净利 | | `财务数据/财务比率.csv` | ✅/⏳ |
| 前提③ | 毛利率 + ROE + 三费率 | | `财务数据/财务比率.csv` | ✅/⏳ |
| 勾稽补 | 货币资金 + 有息负债 + 利息收入 | | `财务数据/资产负债表.csv` | ✅/⏳ |
| 勾稽补 | 预付款 + 其他应收 + 其他流动 | | `财务数据/资产负债表.csv` | ✅/⏳ |
| 特有 | 行业/公司独有指标（每项一行） | | `财务数据/<主题>.csv` | ✅/⏳ |

> 表内有 ⏳ 也可进 Step 3（数据本来就可能缺），但**不允许省略这一步**——不显式列出 = 走过了"先提取后总结"这一硬闸。

### Step 3：风险预警（先勾稽，后红旗 + 分级·全部带数据依据）

> **🚨 硬 gate**：3.0 勾稽表 6 条必须**全部有判定（🔴/🟡/🟢/⏳）**，不允许留空；3.1 通用红旗必须**逐项对照造假模式库扫描一次**；3.2 特有红旗必须**加载行业模板对应块**逐项判定。任一未完成 → 不许进 Step 4 写"六、小结"。

- **3.0 三表勾稽自查表**（规则 Step 3.0）：6 条矛盾按顺序对，🔴/🟡/🟢 分级；命中的写"差额堰塞在哪个鼓包科目"
  1. 利润 ↔ 经营现金流
  2. 营收 ↔ 收现 ↔ 应收
  3. 货币资金 ↔ 有息负债/利息
  4. 累计净利 ↔ 净资产增长
  5. 资产扩张 ↔ 现金来源
  6. 利润 ↔ "垃圾筐"科目
- **3.1 通用红旗清单**：**对照 `knowledge/造假案例库/造假模式库.md` 逐项扫描**（这是随真实造假案例增长的活清单；规则 Step 3 表为速查种子）
- **3.2 公司/行业特有红旗**：`<公司>/财报关注要点.md`（新公司从行业模板套）。**命中已知行业时**（白酒/银行/周期/平台/医药/制造），除公司文件外务必加载 `_模板/财报关注要点-行业模板.md` 对应行业块——公司文件可能只放交叉引用，行业块才是该行业完整雷达（如白酒「批价倒挂 + 收现÷确认营收 + 表外渠道库存」sell-in 压货雷达，报表干净 ≠ 安全）

逐条标 🔴 暴雷嫌疑 / 🟡 需关注 / 🟢 正常 / ⏳ 数据待补，每条**带数据依据**。**判定完整性 = 3.0 六条 + 3.1 造假模式库全清单 + 3.2 行业块全清单，缺一格 = gate 未过。**

### Step 4：写/刷新三件套

**4a · `财务数据/`**（数字真源）：
- 写/扩展 `_build_from_pdf.py`（LLM 提取 + 内置勾稽校验，校验不过不写出 CSV）
- 通用：`利润表.csv` / `资产负债表.csv` / `现金流量表.csv` / `财务比率.csv`（派生）/ `分部营收.csv`
- 公司/行业特有：按需建 `PPE明细.csv` / `基酒产能.csv` / `不良率.csv` / `<主题>.csv`
- `README.md` 更新覆盖年份 + 数据血缘 + 勾稽校验状态

**4b · `分析.md`**（套 `_模板/分析模板.md`）：
- **公司分析速览**：生意类型 / 生意质量(护城河) / 三大前提(✅/⚠️/❌) / 排雷结论 / 核心逻辑是否变坏 / 一句话画像
- **一、关键财务数据**（指针式引用 `财务数据/<csv>`，**不复制数字**，只做概括如"近 6 年毛利率 58–60%"）
- **二、商业模式与生意质量**：① 靠什么挣钱 ② 钱能不能回款 ③ 行业链地位强不强 ④ 前瞻增长的事实面（只摆事实，增速假设是估值动作的输入、不在本文）
- **三、三大前提验证**：每条 ✅/⚠️/❌ + 依据
- **四、最新经营跟踪**：最新一期财报关键变化的事实描述
- **五、排雷与风险**：Step 3 的勾稽表 + 通用红旗 + 公司特有，每条带数据依据；明示"勾稽干净 ≠ 无风险"
- **六、小结**：生意质量定性、核心逻辑有无变坏。**不含"该不该买/估值/仓位"**——本项目不沉淀这些主观决策

> 模板顶部「事实编年核对至：YYYY-MM-DD」要更新到本次刷新时读到的 `knowledge/companies/<公司>/` 最新事实日期。

> **🚨 数字指针体检 gate（写完 `分析.md` 必做）**：每一处出现具体数字（营收/净利/毛利率/比率/占比/绝对值…）**必须紧跟 `财务数据/<csv>` 指针**（或"详见 …"引用）。全文自检一次——**任一裸数字未带指针 = 违反"分析.md 不复制数字"的铁律**。概括式描述（如"近 5 年毛利率 58–60%"）可保留数字，但仍要在段末引指针。

**4c · `财报关注要点.md`**（套 `_模板/财报关注要点-行业模板.md` 最近行业）：
- 生意一句话 + 生意类型 + 🅰 生意模式/原材料/护城河本质 + 🅱 风险雷达
- 核心跟踪变量（3-5 个）：指标 + 频率 + 警戒线 + 触线动作（每项标注数据落点 → `财务数据/<csv>`）
- 公司独有红旗 + 历史踩过的坑/管理层诚信记录
- 持续监控节奏（月度/半年报/年报/事件触发）
- **不嵌数字**——指标的时间序列建对应 `财务数据/<主题>.csv`
- 现有行业模板：白酒、银行、周期、互联网平台、医药、制造重资产。**没有完全匹配的行业 → 选最近的 + 通用骨架，逐项问"这门生意靠什么赚钱、最容易在哪暴雷"，把答案变成 3-5 个跟踪变量**（如农夫山泉无现成块，新建"包装水/饮料快消"行业块）

### Step 5：输出总结（给用户）

格式：

1. **本期/本次关键数据提取**（Step 2 的清单 + 落点 `财务数据/<csv>` 指针）
2. **生意类型 + 三大前提复核**（每条 ✅/⚠️/❌ + 一句话依据）
3. **🔴 风险预警（分级）**：把 🔴/🟡 项汇总成一段（三表勾稽矛盾 + 通用红旗 + 公司特有），每条带数据依据；勾稽命中的指明"差额堰塞在哪个科目"；无 🔴 也要说明"本期未触发已知红旗 ≠ 无风险"
4. **核心跟踪变量**（要继续盯什么·指向 `财报关注要点.md` 的监控规格）
5. **改了哪些文件**（财务数据/ + 分析.md + 财报关注要点.md，及版本变化）

**不输出**：估值/合理 PE/买卖点/能力圈/仓位/操作 —— 这些是主观决策·待重新设计。
