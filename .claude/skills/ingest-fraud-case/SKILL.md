# ingest-fraud-case · 造假案例录入 + 特征蒸馏

把用户给的造假公司案例 → 结构化归档 → **增量蒸馏成可复用的造假红旗**，喂给风险预警。

> 与大V侧同构：`ingest-guru`（蒸馏大V理念）↔ 本 skill（蒸馏造假特征）。
> 产出双层：单案例归档 `<公司>/<公司>-<年>.md` + 跨案例蒸馏 `造假模式库.md`。

## 何时激活

- 用户贴造假公司的**处罚决定书 / 做空报告 / 年报异常数据 / 造假经过** + 公司名
- 用户说"这是个造假案例，归档/总结""学习这家怎么造假""把它的特征加进风险预警""总结造假公司的财报特点"
- 在 `knowledge/造假案例库/` 下看到待补充的案例

## 工作流

### Step 1 · 确认案例身份
- 公司 / 代码 / 造假区间 / 曝光时间 / 曝光方 / 处罚结果 / 造假金额 / 手法标签。
- 缺的先问用户或标 `⏳待补`，**不编造数字**（来源以处罚决定书/做空报告为准）。

### Step 2 · 归档单案例 → `knowledge/造假案例库/<公司>/<公司>-<年>.md`
- 每家公司一个目录；案例 .md 与该公司处罚决定书/调查报告原始档案同放此目录。
- 从 `_案例模板.md` 复制骨架填写。
- **核心是第 2 节「财报上的信号」**：只记**事发前公开财报/数据里就能看到的异常**（存贷双高、毛利离群、增收不增现金…），不记事后才知道的内幕——目的是训练"提前识别"。
- 每条信号标：当时数据表现 / 哪张表科目 / 事后能否被识别。

### Step 3 · 蒸馏增量 → `knowledge/造假案例库/造假模式库.md`（★关键）
- 把本案的信号归到五类之一（A 虚增收入 / B 虚增资产 / C 隐藏负债费用 / D 现金流操纵 / E 治理信号）。
- **已有该模式** → 在对应行的「来源案例」登记本案（把 `种子·待案例验证` 替换/补成真实案例链接），必要时升级级别或细化识别方法。
- **新手法** → 在对应类新增一行（信号 + 识别方法/勾稽 + 级别 + 来源案例）；全新大类则新建一节。
- 更新「已归档案例索引」+「跨案例共性口诀」+「更新记录」。

### Step 4 · 报告
- 1-2 句：本案贡献了哪些**新红旗 / 强化了哪些**，造假模式库现覆盖多少案例/多少红旗。

## 蒸馏标准（怎么算"特征"）

- **可识别**：只沉淀财报/公开数据里看得到的；"内部人举报"不是特征。
- **可操作**：落到"看哪个科目/算哪个比率/和谁横比"，不是空泛的"治理差"。
- **带勾稽**：尽量给交叉验证方法（净利 vs 经营现金流、应收 vs 营收、货币资金 vs 利息收入率、毛利率 vs 同业）。
- **分级**：🔴 命中优先排除 / 🟡 追因定性；严重度看公司语境（高商誉对连续并购者是常态）。

## 注意事项

- **不编造具体公司数字**；处罚决定书没写的标 `⏳待补`。
- **只记当时可见信号**，不做事后诸葛。
- **一次一个案例**，多个分多次，避免信号张冠李戴。
- 蒸馏是**增量**：不重写整个模式库，只在对应模式登记/新增（同 style.md `## YYYY 新增` 思路）。
