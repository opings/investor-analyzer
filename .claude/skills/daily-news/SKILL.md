# 每日新闻监控 + 事实核验 + 事件归档

> 本 skill 不是「新闻推送器」，是「**事件核验归档器**」。价值在用已有知识库当过滤器：
> 一条新闻值不值得入库，取决于它**能否核实为客观事实**，以及**是否构成公司层面的重大事件**。

## 何时使用

- 用户说「查下今天的新闻 / 跑下每日监控 / 今天有什么事」
- launchd 每日 16:00 headless 自动触发
- 用户问「<某持仓公司> 最近有什么新闻」（可只跑单家）

## 何时不用

- 估值/买卖点 → `valuation-method`；财报补数据 → `caibao-analysis`；大V观点 → `guru-view`/`tangchao`/`duanyongping`

---

## 三条铁律（不可违背）

1. **事实优先，宁漏勿错**：写进事实编年的每一条，必须能追溯到**一手或权威来源**——交易所公告、公司 IR/官网、年报/公告原文、监管机构、或权威财媒**引述上述来源的原文**。
   **研报观点、自媒体、"据传/市场传闻/有消息称"、未经证实的爆料 → 一律丢弃，绝不入库。** 被丢弃的在日报里留痕（写明丢了什么、为什么），但不进知识库。
2. **不越界**：事实编年只写「日期 + 主体 + 事件 + 来源」，**不写判断**（贵不贵/该不该买进 finance 或 guru-view）。**大V个人持仓动作不进**（归 `gurus/<昵称>/calls`）。主体限公司本身/董事会/控股股东/高管/监管。
3. **不自动决策**：撞库命中只在日报里给「🔴 建议触发 XX 重估」标记，**不自动改估值数据**，是否重估由用户拍板。

## 执行流程

### Step 0 — 读清单与时间
- 读 `knowledge/companies/_watchlist.md` 拿全部公司 + 代码 + 关注点（清单为准，勿写死家数）。
- 确认今天日期（`currentDate`）。搜索窗口 = 近 1–2 个自然日（含港股收盘后 + 隔夜海外）。
- 单家模式：用户只问某一家，则只跑那家。

### Step 1 — 拉一手公告（事实主源：akshare/cninfo）
**先跑脚本**，从巨潮(cninfo)拿全 watchlist 当窗口的一手公告清单（A 股+港股通用）：
```
python3 scripts/notices.py <起始日> <结束日>     # 省略=今天；只给起始=单日
```
- 输出按公司分组：`公告时间 | 公告标题` + cninfo 一手链接。例行公告（翌日披露报表/法律意见书/监事会决议等）已折叠并报数。
- 这是**事实主源**：cninfo 标题即客观事实，链接即一手出处，天然带日期、不会漏当日公告。
- 脚本复用 `scripts/.venv`（akshare），无需手动激活；「窗口内无公告」是常见且正常的结果。

### Step 1b — WebSearch（补充源，非主源）
仅在以下情况用 WebSearch / WebFetch，**不再用它当主源**：
- 公告标题信息不足、需要展开细节 → WebFetch 对应 cninfo 链接拿正文，或搜权威财媒解读。
- 港股某些经营动态（交付量、联名、舆情）不一定有 cninfo 公告 → 围绕「关注点」补搜。
- 对脚本捞到的关键数字做交叉核验。
采信顺序：cninfo 公告原文 > 港交所/公司 IR > 证券时报/财联社等**引用公告原文**的报道 > 其他。

### Step 2 — 事实核验闸门（核心）
对每条候选（公告 or 搜索结果），逐条判：
- 来自 `notices.py` 的 cninfo 公告 → 已是一手事实，直接进重大性判定。
- 来自 WebSearch 的 → **可核验为事实？** 能指向一手/权威来源 → 留；只是观点/传闻/未证实 → **丢弃，记入日报「丢弃区」**。
- 模糊时降级处理：宁可标「待核实」放日报，也**不**写进编年。

### Step 3 — 重大性门槛
通过核验的事实，再判是否「重大」（够格入编年）：
- ✅ 入编年：
  - **资本/治理类**：业绩预告/快报/定期报告、分红/回购/增减持、重大资本运作（并购/重组/定增/分拆上市）、监管处罚/立案/问询、重大诉讼、高管/实控人变动、列入/移出实体清单等制裁。
  - **经营/产销类**：关键产销数据（如月度交付量、批价异动）。
  - **营销/产品节点类**：重大新品发布、重要 IP 联名/合作、关键渠道或定价动作、重大营销战役（如世界杯联名）——**凡可能影响后续营收的经营节点都记**。营销活动的「时间」与其「后续效果」（销量/营收/价格表现）都是会影响营收的客观事实，应分别按发生时间逐条入编年。
  - 判定标准：**是否可能影响这家公司未来的营收/利润/竞争格局**。是 → 入编年（只记客观事件本身，不预判效果好坏，效果以后续数据形式继续入编年）。
- ⬜ 只进日报不入编年：与营收无关的纯日常公告、行业一般新闻（非本公司主体）、已在编年里的事项的重复报道。

### Step 3.5 — 白酒批价阶梯（白酒公司每次必抓·头号表外温度计）

> 白酒「报表干净 ≠ 安全」，真实需求看**表外批价**。**6 家白酒（茅台 / 五粮液 / 泸州老窖 / 山西汾酒 / 古井贡B / 洋河）每次监控必抓核心单品的「价格四阶梯」**，按统一格式记入事实编年——这是 sell-in 压货 / 真实动销的头号探针（五粮液 2026 实证：批价倒挂坐实压货，见 `knowledge/造假案例库/五粮液/`）。

**价格四阶梯（缺哪档标「待查」，不编）：**
1. **出厂价(打款价)** —— 厂家对经销商官方挂牌价（变动少，可沿用上次值）
2. **开票价** —— 实际开票价（含直降/补贴后，如五粮液普五 2026 直降 119→900）
3. **批价(渠道流通价)** —— 经销商间流通/真实成交价（**核心**）
4. **电商终端** —— 天猫/京东等终端零售（含平台补贴）

**判定**：批价 vs 出厂价 → 守价/供不应求（批价≥出厂）还是 **倒挂（批价<出厂）🔴**，标倒挂幅度。倒挂 = 合同负债是「虚水位」而非安全垫。

**标准格式**（一次快照一行，记入 `companies/<公司>/YYYY-MM.md`）：
`| YYYY-MM-DD | <公司> | 批价快照·<核心SKU>：出厂(打款)X / 开票Y / 批价Z / 电商W；vs出厂{倒挂N%🔴 / 守价} | [来源](URL) |`

**核心单品（高端信号 + 基本盘量，2-3 个/家）**：茅台=飞天(散瓶/原箱)+1935(系列酒次高端)；五粮液=第八代普五+1618；泸州老窖=国窖1573+特曲(中端基本盘)；汾酒=青花20/30+玻汾(光瓶塔基量)；古井=古20/古16+古8(中端口粮基本盘)；洋河=梦之蓝M6+/M9(高端)+海之蓝(基本盘量)。
> **分档逻辑**：每家盯「高端单品(倒挂/提价信号) + 基本盘量单品(动销信号)」——高端看价、口粮看量，二者背离常是消费降级的早期信号(如古井 2026：高端古20倒挂🔴 / 中端古8稳)。
**频率**：每次监控必查；**批价有实质变动、或每周至少一次** → 追加一行；与上次完全相同则不重复刷屏（dedup）。来源用今日酒价/酒说类行情页或权威财媒，务必带日期。

### Step 4 — 去重后写入事实编年
对每条「事实 + 重大」的事件：
- 打开 `knowledge/companies/<公司>/<时段>.md`（默认 `YYYY-MM.md`；遵守 INDEX 的粒度约定，同一时段只用一种粒度）。文件不存在则从 `_模板/事实编年.md` 起一个。
- **去重**：与该文件已有条目比对，同一事件不重复录入。
- **倒序**（最新在上）追加一行：`| YYYY-MM-DD | 主体 | 事件 | [来源](URL) |`。来源务必带真实 URL；暂缺标「待补」。
- 若该公司事实编年首次有内容 → 把 `INDEX.md` 对应行「事实编年」列改 `✓`。

### Step 5 — 撞库（只给建议，不动数据）
对入编年的事件，做两个轻量交叉检查：
- **造假模式库**：事件是否命中 `knowledge/造假案例库/造假模式库.md` 的某条预警特征（如存贷双高、商誉异常、大额关联交易）？命中 → 日报标 `🔴 建议触发风险复核`。
- **估值假设**：事件是否打破 `finance/<公司>/分析.md` 里的某条关键假设（如增速、分红率、产能）？是 → 日报标 `🔴 建议触发 caibao-analysis / valuation-method 重估`。
- 大V逻辑：事件是否印证/推翻某大V对该标的的观点？可在日报标 `🟡 可喂 guru-view 复盘`。

### Step 6 — 产出当天日报
写 `report/daily/YYYY-MM-DD.md`（见下方模板）。日报是**审计凭证**：既记入库了什么，也记丢弃了什么传闻、为什么。

### Step 7 — 收尾摘要
向用户（或 headless 日志）输出一句话摘要：今天扫了 N 家，给 M 家共追加 K 条编年，R 个 🔴 待你决策。

---

## 日报模板（`report/daily/YYYY-MM-DD.md`）

```markdown
# 每日监控 · YYYY-MM-DD（收盘后）

## 摘要
- 扫描 N 家｜入编年 K 条（M 家）｜🔴 待决策 R 项｜丢弃传闻 J 条

## 入编年（已核实·已写入知识库）
- **贵州茅台** → `companies/贵州茅台/2026-06.md`
  - YYYY-MM-DD 控股股东集团增持进展公告，累计增持 X 亿元 [来源](URL)
  - 🔴 建议触发 valuation-method 重估（理由：…）  ← 如有

## 仅日报（已核实·未达重大门槛或属背景）
- **腾讯控股** 视频号商业化进展报道（常规经营动态，不入编年）[来源](URL)

## 丢弃（未核实/传闻，不入库）
- **赛力斯** "据传某新车型 7 月发布" —— 仅自媒体，无公司公告，丢弃
- **农夫山泉** 某舆情贴 —— 无一手来源，丢弃

## 🔴 待你决策
1. <公司> <事件> → 建议触发 <skill>
```

## 注意

- **宁可少报**：一天没有重大事件是常态，如实写「今日无重大事件入库」即可，不要为了凑数把背景新闻拔高成重大。
- **来源 URL 真实**：严禁编造链接。查不到一手来源的，要么标「待补」放日报，要么丢弃，**不入编年**。
- **不改 finance 数据**：本 skill 只读 `finance/` 做撞库判断，绝不写估值数字（那是 `caibao-analysis` 的活）。
- **headless 模式**：自动运行时无人交互，遇到拿不准是否「重大/可核实」的，一律降级到「仅日报/待核实」，把判断留给人。
