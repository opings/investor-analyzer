# 财报分析流程（唐朝体系）

> 估值库根目录：`finance/`（含 README、`_模板/`、`组合/`、各公司目录）。

## 何时使用

- 用户粘贴 / 口述某公司财报数据（扣非净利、营收、合同负债、资本开支、分红等）
- 用户说「<公司> 出了 <期> 财报，补进去 / 更新一下」
- 用户要求重算估值买卖点、刷新某公司 `分析.md`

## 何时不用

- 纯粹问「老唐怎么看 XX」的观点类问题 → 用 `tangchao` skill
- 不涉及财报数据的闲聊

---

## 铁律（不可跳过）

1. **先提取，后总结**：必须先按规则逐项提取关键数据并列出，再下结论。**严禁凭印象直接给买卖点 / 结论。**
2. **不编造**：财报里没给的数据，标 `⏳待补`，不要猜数填进去。
3. **单一真相**：估值公式/双闸门以 `valuation-method` 为准、通用红旗以 `knowledge/造假案例库/造假模式库.md` 为准、三大前提取数流程在 `财报阅读规则.md`；本 skill 只按序执行、不重抄。
4. **观点变更只增不改**：`finance/<公司>/观点变更.md` 是判断演变历史，刷新 `分析.md` 时**绝不覆盖/删改它**；本次若改了评级/买卖点/论点，往它顶部**追加**一条带日期的记录。

---

## 执行流程

### Step 0：事实底座前置门槛（缺则先补，再分析）

> 见规则 `财报阅读规则.md` 的「Step −1」。分析前**必须确认两样到位，缺了先补**：
1. **近 10 年年报+季报三表** → `finance/<公司>/_raw_akshare/*.csv`；没有就 `python3 scripts/fetch_fundamentals.py <代码> <公司名>`（不足 10 年尽量拉）。关键期双源(新浪/东财)交叉验证 + 三表自洽检查；**不手数 CSV 列，按列名脚本提取**。
2. **近 3 年事实编年** → `knowledge/companies/<公司>/YYYY-MM.md`；没有就先补一手公告/事件。

### Step 1：读规则（每次必读，按顺序）

1. 读 `finance/_模板/财报阅读规则.md` —— 通用 SOP（估值法判断 / 估值取数 / 三大前提 / 排雷 / 输出纪律）
2. 读 `finance/<公司>/财报关注要点.md` —— 该公司特有看点。**若不存在 → 本次必须新建**（从 `_模板/财报关注要点-行业模板.md` 套最近行业骨架起，沉淀 生意模式/护城河本质 + 核心跟踪变量 + 独有红旗）。**这是流程强制产出，与 `分析.md`/`观点变更.md` 同级——不再是"提示可补建"的软提示**（历史漏建 7 家的教训：软提示必被跳过）。

### Step 2：判断估值法

按规则 Step 0 确认是**成长股（老唐估值法）**还是**周期股（席勒法）**——决定看单年增速还是十年均值。

> 📐 估值法**选择逻辑、双闸门（生意质量四问 + 三大前提）、三类公式**以 `valuation-method` skill 为 canonical 源；本 skill 不重抄公式。本 skill 只负责财报可验证的「三大前提」取数与复核；「生意质量四问」是定性护城河判断（非财报直接可得），由 `valuation-method` / `invest-report` 承接。需要正式定买卖点时直接走 `valuation-method`。

### Step 3：按清单提取并列出「本期财报关键数据」

对照规则 Step 1-3 + 公司关注要点，逐项提取并**显式列出**：
- 估值硬数据（扣非净利 / 营收增速 / 次年经营计划）。**成长股当年净利(基准年)= 当期最新季报实数 × 历史同期占比反推**（xlsx `季度占比` sheet）；**下行/崩盘年用崩盘年高占比、不可用正常年均值**（否则下行期反出荒谬高增；见 [[laotang-valuation-base-year]]，茅台/古井实证）
- 三大前提验证数据（经营现金流、合同负债、应收、资本开支、毛利率…）
- 三表勾稽补充取数（货币资金、净资产、利息收入、预付/其他应收——规则 Step 2④，供 3.0 勾稽用）
- **风险预警扫描（先勾稽，后红旗 + 分级）**：① **三表勾稽自查**——先按规则 Step 3.0「三表勾稽自查表」顺「利润→现金→资产」链找断点，定位假利润堰塞在哪个鼓包科目（这一步**先做**，给红旗清单指方向）② 通用红旗——**对照 `knowledge/造假案例库/造假模式库.md` 逐项扫描**（这是随真实造假案例增长的活清单；规则 Step 3 表为速查种子）③ 公司/行业特有项（`<公司>/财报关注要点.md`，新公司从 `_模板/财报关注要点-行业模板.md` 套行业起步）。**命中已知行业时（白酒/银行/周期/平台…），除公司文件外务必加载 `_模板/财报关注要点-行业模板.md` 对应行业块——公司文件可能只放交叉引用，行业块才是该行业完整雷达**（如白酒「批价倒挂 + 收现÷确认营收 + 表外渠道库存」sell-in 压货雷达，报表干净≠安全）。逐条标 🔴 暴雷嫌疑 / 🟡 需关注 / 🟢 正常，**每条带数据依据**。
- 缺失项标 `⏳待补`

### Step 4：更新 xlsx（`finance/<公司>/<公司>.xlsx`）

- 估值表：新增「年份 | 扣非净利 | 增速」行，更新当年净利基数
- 季度 / 营收表：填最新期
- 买卖点公式以 `valuation-method` 为准：**方法已确认时** caibao 可按该方法重算参数并回写 +「买卖点历史」追加带**日期**快照；**方法未定/首次分析 → 只更新净利基数，买卖点留给 `valuation-method`**（不自套公式、不绕双闸门）
- 用 openpyxl 操作（写 `/tmp/*.py` 脚本；注意公式单元格，data_only 读不到公式本身）
- **铁律：每次 openpyxl 保存后，必须设 `wb.calculation.fullCalcOnLoad = True` 再 `wb.save()`。** openpyxl 写入公式不会算出值，缓存仍是旧值；置此标志后任何表格软件打开会自动重算，避免「看着像没补全」的误导，也省得手动触发重算。

### Step 5：刷新 `finance/<公司>/分析.md`

按规则 Step 4：净利历史表加行、三大前提把 `⏳待补` 换成实数并重判 ✅/⚠️/❌、估值与买卖点、风险排查、核心跟踪变量、文末「数据截止」。
**并刷新顶部「投资决策（结论速览）」块**（模板见 `_模板/分析模板.md`）：生意质量(护城河) / 三大前提 / 能力圈 / 可估值性 / 评级 / 最高仓位 / 买卖点 / 现价位置 / 操作 / 一句话论点 / 核心跟踪变量。**能力圈、最高仓位、操作 用户未明示就保持 `待定/待填`，不替用户拍板**；新建公司的 `分析.md` 必须含此块。

> 评级四档：好生意 / 一般(周期股或有瑕疵·可估值博弈) / 太难(无法估值·能力圈外) / 回避(曾好但核心逻辑已坏)。**评级是对生意的判断、与持仓无关**；周期/暂时性⚠️不把强护城河降出"好生意"。**大V的清仓/建仓等动作不进本块**（归 gurus / 观点变更.md 背景）；「操作」只记分析阶段意图(买入区/观望/回避)，持有/减仓/清仓等有持仓后再用。

### Step 5.5：判断若变了，追加 `观点变更.md`（只增不改）

对比上一版，本次若 **评级 / 可估值性 / 买卖点 / 核心论点** 发生变化，就在 `finance/<公司>/观点变更.md` **顶部追加一条**（最新在上）：
`YYYY-MM-DD 变更类型:前→后 | 为什么（数据依据）`（格式/类型见 `_模板/观点变更.md`）。
- **绝不覆盖或删改已有条目**（不可变历史，刷新 `分析.md` 不动它）。
- 文件不存在就从模板新建，首条写 `首次建库`。
- 只记结论级变化 + 依据；纯数据补全（没改结论）可不记。

### Step 6：同步

- `finance/README.md` 状态表的「数据截止」列
- 若涉及仓位变化，提示更新 `finance/组合/持仓.xlsx`

### Step 7：输出总结（给用户）

格式：
1. **本期财报关键数据提取**（Step 3 的清单）
2. **三大前提复核**（每条 ✅/⚠️/❌ + 一句话依据）
3. **🔴 风险预警（分级）**：把 🔴/🟡 项汇总成一段（三表勾稽矛盾 + 通用红旗 + 公司特有），每条带数据依据；勾稽命中的要点明"差额堰塞在哪个科目"；无 🔴 也要说明"本期未触发已知红旗 ≠ 无风险"。
4. **估值与买卖点**（新买点 / 卖点 + 相比上期变化）
5. **变化与跟踪**（核心变量有无异动、要继续盯什么）
6. 改了哪些文件（含 `观点变更.md` 本次是否追加条目及内容）
