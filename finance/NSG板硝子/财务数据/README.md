# NSG（日本板硝子） 财务数据（从一手财报 PDF 解析）

> 本目录 = 日本板硝子株式会社（5202.T·东证 Prime）的**一手财务数据库**：从一手 有価証券報告書 解析的所有客观数字统一落点。
> 公司分析 → `../分析.md`；监控规格 → `../财报关注要点.md`；事件 → `knowledge/companies/NSG板硝子/`（分层不混）。

> **数据血缘**：全部 CSV 数字 = 从 `report/NSG板硝子/` 的 **26 份 有価証券報告書**（第135–160期）**文本层确定性解析**
> （poppler `pdftotext -layout` → 概念锚定解析器 `_extract.py` → `_extract_json/fy*.json` → `_build_from_pdf.py` 五重校验，**校验不过不写出**）。
> **单位/符号**：**百万円**（年报原始口径）。日文报表「**△**」= 负号，提取层已转为负数；IFRS 段费用/流出以负数列示，JGAAP 段以正数列示（毛利率等派生一律取 `abs`）。空 = 该年未披露该科目。
> **本目录是 NSG 数字的唯一真源**——`分析.md` / `财报关注要点.md` 引用本目录，不复制数字。

## 财年口径（先看这条，否则每个年份都会错一年）

NSG 是 **3 月决算**。本库列名 **`FYxxxx/3` 指「截至该年 3 月 31 日的财政年度」**：
`FY2026/3` = 2025-04-01 ~ 2026-03-31 = **第160期**。**第N期 ↔ 财年**换算：`FY = N − 134 + 2000`。

### 回溯层（FY1997/3–FY2000/3）：PDF 拿不到，但数据拿得到

常规取数原则是「只认该年自己那份年报的当期列」。**FY2000/3 及以前没有自己的年报可得**（上节实证），
此时**最早一份年报（第135期）内部就是这些年份的唯一一手来源**——与「招股书是上市前 3 年唯一真源」同理：

- **FY2000/3**：第135期 有報 的**前期列**给出完整三表（损益 9 项 / 财政状态 20 项 / 现金流 6 项）。
- **FY1997/3–FY1999/3**：第135期 有報 的「主要な経営指標等の推移」5 年表覆盖**第131–135期**，
  给出 売上高 / 経常損益 / 当期純損益 / 純資産額 / 総資産額 / 1株当たり指標 / 自己資本比率 / ROE / PER
  （CF 三行与現金期末残高自第133–134期起才有——日本自 FY2000/3 前后才强制连结现金流量表）。
- **第⑥层校验**：把「第135期前期列」与「同一份报告 5 年表的第134期列」逐格对——**7 项 0 差异**，
  两者在同一份 PDF 的不同章节独立印刷，对得上才敢把回溯年当一手数用。
- 后续 FY2002/FY2003 报告的 5 年表仍覆盖第131–137期，构成**第 2、3 重独立印证**（第③层已跑，一致）。

> **教训**：建库首轮把这四年写成「实证不可得」，其实只探了 PDF 这一条路。
> **「某年的年报拿不到」和「某年的数据拿不到」是两件事**——年报里的 5 年表与比较列是天然的回溯层。

**准则断点**：`利润表.csv` / `资产负债表.csv` 中 JGAAP 专有科目（経常利益 / 固定資産合計 / 少数株主持分 / 純資産合計…）与 IFRS 专有科目（個別開示項目 / 非流動資産合計 / 親会社所有者帰属持分…）**分行列示，不做跨准则拼接**。`长期业绩序列.csv` 的「経常損益[JGAAP]」行只在 JGAAP 段有值——**JGAAP 的経常利益与 IFRS 的税引前利益不是同一口径，不可连成一条曲线**。

## 取数原则：只认「该年自己那份年报的当期列」

每一年的数只取**该年 有報 的当期列**（as-reported），**后续年度报告的「前期列」不用来覆盖，只用来互证**。
原因：NSG 有多次**遡及修正**，比较列 ≠ 当年原始披露值；用比较列覆盖等于把历史悄悄改写成「重述后」的样子且无从追溯。已识别并逐条核对到会计政策变更注记的重述：

| 被重述年 | 在哪份报告里被改 | 变更内容（一手来源） | 主要差异 |
|---|---|---|---|
| FY2013/3 | FY2014 有報 | **IAS 19（従業員給付）改訂适用**，按 IAS 8 修正比较信息【FY2014 有報 P5 注5】 | 税引前 −29,068 → −31,096；当期损益 −32,808 → −34,324 |
| FY2014/3 | FY2015 有報 | **英国主要年金制度的「资产上限额(asset ceiling)」会计政策变更**（IFRIC 14 相关）【FY2015 有報 P5 注5】 | 负债合计 750,677 → 732,722；总资产 925,175 → 926,208 |
| FY2018/3 | FY2019 有報 | **IFRS 15「顧客との契約から生じる収益」适用**，汽车玻璃模具收入改为交付时点确认，遡及适用【FY2019 有報 P5 注5】 | 売上高 603,852 → 598,897；営業CF 37,163 → 34,716 |
| FY2021/3 | FY2022 有報 | **持分法适用公司相关损益的列报方法变更**（金融债权减值/投资其他损益单列）【FY2022 有報 P5 注5】 | 営業損益 −8,329 → −8,884 |
| FY2016/3 前后 | — | **2016-10-01 普通股 10 股并 1 股（株式併合）**【FY2020 有報 P1 注4】 | 每股指标断点：1株当たり純資産 114.14 → 1,141.40 等 **×10**，非重述 |

## 校验（`_build_from_pdf.py`，①④⑤ 全过才写出 CSV）

**① 表内勾稽**（按准则分别校）
- IFRS：売上高+売上原価=売上総利益 · 毛利+その他収益+販売費+管理費+その他費用=個別開示項目前営業利益 · 税引前+法人所得税(+米国税率変更調整)=当期利益 · 親会社帰属+非支配持分帰属=当期利益 · 流動+非流動=資産合計 · 流動負債+非流動負債=負債合計 · 親会社持分+非支配持分=資本合計 · 負債+資本=負債及び資本合計=資産合計 · **営業+投資+財務=増減額** · **期首+増減額+換算差額+超インフレ調整+売却目的振替=期末**
- JGAAP：売上高−売上原価=売上総利益 · 売上総利益−販管費=営業利益 · 流動+固定=資産合計 · 流動負債+固定負債=負債合計 · 負債+(少数株主持分)+純資産=資産合計
- **结果：FY2001/3–FY2026/3 共 26 年、全部通过**

**④ 完整性闸**：核心行（IFRS 15 行 / JGAAP 13 行）必须每年取到值——勾稽遇 `None` 会跳过而非报错，单科目整列丢失能瞒过勾稽。**结果：0 缺失**

**⑤ 5 年表 ↔ 三表 同源互证**：同一份报告里，「主要な経営指標等の推移」印的本年数 vs 三表本年列，10 个指标逐格对。这是判断 5 年表各行**有没有被映射错**的决定性检验（行名折成 3-4 行时极易串行，单看数字看不出错）。**结果：26 份报告、0 处差异**

**② 跨源互证**：报告 Y+1 的「前期列」 vs 本库 Y 年当期值，6-7 关键行 × 25 对年份。**结果：差异仅出现在上表 4 次遡及修正处，其余 0 差异**

**③ 5 年表跨报告互证**：每份 有報 的 5 年表覆盖 5-8 列，同一年份最多被 5 份报告独立印过 → 逐格比对。**结果：差异同样只落在 4 次重述 + 1 次股份合并处**

**分部校验**（`_build_segments.py`）：各分部外部売上高之和 vs 合計列，**FY2012/3–FY2026/3 共 15 年全部相等**；当期块 vs 次年报告前期块逐格互证，**差异只出现在 FY2018/3（IFRS15 重述）与 FY2021/3（列报变更）**。

## 重要口径注记（踩过的坑）

1. **【读取器决定成败：pypdf 读不了、poppler 能读】** FY2001/3–FY2005/3（第135–139期）用 pypdf 抽出来是**乱码**（CID 字体映射不支持，「有価証券報告書」抽成 `ɹ༗ɹ༗…`），一度被判为「文本层损坏、不可解析」；**换 poppler `pdftotext -layout` 后同样这几份文件完整可读**——多拿回 5 个年份。**「文本层坏」往往是读取器的问题，不是文件的问题**。（AGC 库把 FY2025 有報 判为损坏改用決算短信，可能是同一个坑，值得回头用 poppler 复验。）
2. **【△ 是负号，但全角「－」是 nil】** 两者必须分开处理。曾把全角「－」并进全角→半角转换表转成 ASCII `-`，结果它既不是数字 token 又不在 nil 字符类里 → **整格被丢掉、后面列全部左移一位**：FY2019/3「米国連邦法人税率の変更に伴う調整額 － △9,590」被读成当期 −9,590（真值为 nil），当年勾稽差 9,590。
3. **【列序在准则断点处翻转，且必须按 x 位置判】** NSG 的 **JGAAP 段是「前期在左」、IFRS 段是「当期在左」**——同一家公司两个方向，写死任何一种都会让半个序列整体错位一年。更麻烦的是 `-layout` 抽文会把表头两个词拆到不同行且**文本顺序与视觉相反**（実測 FY2022/3：「前連結会計年度」排在上一行、「当連結会計年度」排在下一行，但 x 位置上当期在左）。**判据必须是横向位置 x，不是出现先后**。
4. **【亏损年份改的是科目名，不是符号】**
   - IFRS 段：亏损年直接写「税引前**損失**」「当期**損失**」「親会社の所有者に帰属する当期**損失**」，不是加「（△は損失）」后缀。只写「利益」会在**恰恰是亏损的那些年**整行丢失——而 NSG 二十六年里亏损年占近一半。
   - JGAAP 段更狠：**亏损行印的是无符号正数**，符号只藏在科目名里（FY2003/3「当期純損失 2,278 … 3,152」其实是 −2,278 / −3,152），且盈亏**各占一行、另一列填 nil**（経常利益一行、経常損失另一行）。照直读会**把亏损读成等额盈利，误差是两倍**。本库按「利益/損失成对行按列合并 + 来自損失行的正值取负」处理，并由 ⑤ 校验兜底（5 年表印的是带 △ 的正确符号）。
5. **【JGAAP 版夹着「構成比／百分比（％）」列】** `流動資産合計 167,724 39.3 288,732 48.4` = [前期額, 前期%, 当期額, 当期%]。判别法：**源串里有没有小数点**——百万円金额一律千分位整数，構成比一律一位小数。**不能改用「值是否为整数」**：構成比 `5.0`/`100.0` 数值上也是整数，実測会漏掉。
6. **【IFRS 段的 BS 小计行没有科目名】** 「非流動資産合計/流動資産合計/流動負債合計/非流動負債合計」印成**裸数字行**，上方只有分块标题「非流動資産」。按科目名找永远找不到 → 这四行整列为空、"流動+非流動=資産合計" 全年全崩（差额恰等于合计本身）。本库按「最近的分块标题」归属、同块取最后一个小计，并在遇到 資産合計/負債合計/資本 等大计行时清空归属。
7. **【页码 `- 85 -` 会被当成数字行】** 解析成一个 −85 的单元格、科目名为空 → 被"无名小计行"逻辑认成「流動資産合計」（実測 FY2020），也会被"折行科目名"第二遍吃掉（実測 FY2013 当期利益 = −58 = 页码）。必须在抽文层就丢掉页码与页脚行。
8. **【NSG 的现金流量表结构与多数公司不同】** ①「増減額」= 営業+投資+財務，**不含**換算差額（換算差額印在増減額**之后**）；② 期末 = 期首 + 増減額 + 換算差額 + **超インフレの調整**（IAS 29，阿根廷/土耳其，FY2019/3 起出现）+ 个别年份的「売却目的で保有する資産への振替に伴う現金増減」（FY2013/3 △149）。照 AGC 那套恒等式写会**年年不平**。
9. **【CF 的现金 ≠ BS 的现金，这是口径不是错】** NSG 现金流量表的「現金及び現金同等物」是**扣除银行透支后的净额**，BS 上透支计入流动负债的借入金、现金按总额列示（FY2012/3 两者差 18,549 百万円）。公司在会计方针里写明。**不要拿这两个数去对**。
10. **【「営業活動による現金生成額」≠ 経営現金流】** 前者是**付息付税前**的 cash generated from operations，后者是净额，两者差一整块利息+税（実測 FY2026/3：63,739 vs 33,624，**差额约占前者的 47%**）。把前者当经营现金流会把经营质量拔高一档——这正是本库记忆里「港股经营业务现金净额实为税前」同类坑的日股版本。
11. **【个别开示项目(exceptional items)是 NSG 的英式列报特色】** 重组/减值/处置常年从这里走，夹在「個別開示項目前営業利益」与「営業利益」之间。**FY2022/3 起由单行拆成「収益」「費用」两行，且「営業利益」改名「個別開示項目後営業利益」**——两套写法都得认，否则近年营业利润整列丢。
12. **【FY2018/3 独有的一次性税项】** 「米国連邦法人税率の変更に伴う調整額」△9,590（美国 TCJA 减税法案导致递延税重估）单列一行，漏掉它当年「税引前+税=当期利益」必差 9,590。
13. **【分部表是两张，不是一张】** A 表「報告セグメントごとの実績」= 收入 + 分部利润；B 表「…個別開示項目前営業利益までの主な項目」= 折旧/摊销/减值/研发按分部拆。按 A 表标题开固定行数窗口去抓折旧，会**滑进下一期的 B 表**、把两期数据混在一起（実測 FY2012–FY2021 折旧全部串成了相邻期数）。且 B 表标题被折成两行、年度写在第一行，锚在第二行会取不到年度、整块被丢。
14. **【分部名在文本里不连续】** 表头竖排折行：一行「建築用 自動車用 高機能 その他 合計」、下一行「ガラス事業 ガラス事業 ガラス事業」，拼起来「建築用自動車用高機能その他合計ガラス事業…」——完整名「建築用ガラス事業」**根本不连续**，按全名匹配一个都找不到。只能匹配前缀短名。
15. **【B 表只覆盖 FY2021/3 起】** 更早年份的 有報 用不同措辞列示分部折旧，本库未强行套用 → `分部营收.csv` 中 減価償却費/償却費/減損損失/研究開発費 四行只有 FY2021/3–FY2026/3 有值。**这是覆盖缺口，不是零值。**
16. **【下载会在最后 1% 超时】** 第159期 PDF（4.4MB）实测在 300 秒超时时已收到 4,341,348/4,386,573 字节。`curl -f` 会删除半截文件、看起来像彻底失败。大文件须放宽 `--max-time`。
17. **🔴【公司自己的 5 年表印错过数——摘要页不可信】** FY2002/3 的投資CF / 財務CF：
    - **5 年表**（FY2002 与 FY2003 **两份**报告）都印 **△36,944 / 2,216**
    - **经审计连结现金流量表**（FY2002 当期列与 FY2003 前期列**逐字一致**）都印 **△36,607 / 2,225**
    - FY2002 报告 MD&A 正文亦写「財務活動…**22 億 25 百万円**のプラス」→ 三处一手证据指向审计报表
    → **审计三表为准，5 年表该两格是跨年度重复的印刷错误**（已在 `_build_from_pdf.py` 的 `SUM_KNOWN_BAD` 里登记，
    第⑤层校验会把它标成「已查实」而非新差异）。**这条正是「三表为准、5 年表只作互证」这个设计的价值——
    若图省事直接拿 5 年表建库，这两格会静默错进去且永远不会被发现。**
18. **🟡【应收账款证券化（債権流動化）规模未披露】** 会计方针载明：应收经流动化方案售予金融机构、
    风险报酬转移即**终止确认**【源：FY2026 有報 P111，FY2020/FY2023 同】，**但 有報 全文未量化售出金额**。
    后果有二：① 资产负债表上的应收是**扣除未知规模已售应收后的净额**；
    ② `应收明细.csv` 里外部顾客应收 ÷ 营收从 FY2012/3 的 17.0% 降到 FY2026/3 的 6.6%，
    **这个「改善」无法区分是经营改善还是售出规模扩大**——不可作为回款质量变好的证据。
19. **【分部 B 表的标题措辞逐年变】** FY2015/3 写「…における、**上記以外の**連結損益計算書に計上**される**、
    個別開示項目前営業利益までの主な項目」，FY2020/3 写「…連結損益計算書に計上**された**個別開示項目前営業利益までの…」。
    锚死后者会让 FY2012–FY2019 的折旧/摊销/减值/研发四行整段为空——**曾据此误判为「早年未披露」，实际一直都在**。
20. **【5 年表的行名会被单位标记从中间劈开】** 「親会社の所有者に帰属する基本的１」/「（円） 数字…」/「株当たり当期利益」——
    数据行自身的"行名"只剩一个单位。须先剥单位标记、再**前后一起拼**才能复原行名。
    ⚠️ 但**拼接方向有先后**：数据行**下面**那条纯文字行往往是**下一行的行名**（実測経常利益行的下一条是「税引前利益」），
    先往后拼会张冠李戴（実測 FY2010–FY2012 三年当期損益被写成経常/税前数）。**顺序必须是：先往前拼 → 自身 → 再往后拼。**
