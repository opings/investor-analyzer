# AGC（旭硝子） 财务数据（从一手财报 PDF 解析）

> 本目录 = AGC株式会社（5201.T·东证）的**一手财务数据库**：从一手 有価証券報告書 / 決算短信 解析的所有客观数字统一落点。
> 公司分析 → `../分析.md`；监控规格 → `../财报关注要点.md`；事件 → `knowledge/companies/AGC旭硝子/`（分层不混）。

> **数据血缘**：全部 CSV 数字 = 从 `report/AGC旭硝子/` 一手 PDF **文本层确定性解析**（pypdf plain 模式 → 概念锚定解析器 → `_extract_json/fy*.json` → `_build_from_pdf.py` 三重校验，**校验不过不写出**）。
> **单位/符号**：**百万円**（年报原始口径）。日文报表「**△**」= 负号，提取层已转为负数；费用/流出以负数列示。空 = 该年未披露该科目。
> **本目录是 AGC 数字的唯一真源**——`分析.md` / `财报关注要点.md` 引用本目录，不复制数字。

- **①三表 CSV**：**IFRS FY2012-FY2025 共 14 年** ✅（FY2012 为 IFRS 移行比较期）；另有 **日本基準 FY2009-FY2013** 长期序列（见 `长期业绩序列.csv`）
- **②事实编年**：`knowledge/companies/AGC旭硝子/{2023,2024,2025,2026}.md` ✅（核对至 2026-03-30）

- **③b 年度报告**：
  - **有価証券報告書（审计版）FY2013-FY2023** ✅ —— AGC 官网静态路径 `agc.com/ir/library/yu_report/pdf/rep{YYYY}_4.pdf`（FY2024 为 `rep2024_3.pdf`，因 2024 年起四半期報告書废止、编号顺延）

> **绕过 EDINET API 的取数路径（本次建库跑通，可复用于其他日本公司）**：
> ① 公司官网静态 PDF（多数日企把 有報/短信 挂在可枚举路径上）；

## 勾稽自洽校验（`_build_from_pdf.py`，①③ 全过才写出 CSV）

**① 表内勾稽 + 完整性 + 连续性 + 分部**（每年 13 条恒等式）
- **损益**：売上高+売上原価=売上総利益 · 売上総利益+販管費+持分法=営業利益 · **営業利益+その他収益+その他費用=事業利益** · 事業利益+金融収益+金融費用=税引前利益 · 税引前+法人所得税=当期純利益 · 親会社帰属+非支配持分帰属=当期純利益
- **财政状态**：流動+非流動=資産合計 · 流動負債+非流動負債=負債合計 · 親会社帰属持分+非支配持分=資本合計 · 負債+資本=負債及び資本合計 · 資産合計=負債及び資本合計
- **现金流**：営業+投資+財務+換算差額+売却目的保有現金=増減額（容差 10）· 期首+増減額=期末 · CF期末現金=BS現金
- **完整性闸**：13 个核心行必须每年取到值（勾稽遇 None 会跳过而非报错，单科目整列丢失能瞒过勾稽）
- **分部**：各分部外部売上高之和 ≈ 連結売上高 · 分部利益之和 ≈ 合計列（容差 20）

**② 跨源互证**：报告 Y+1 的「前期列」 vs 本库 Y 年值，6 关键行 × 13 年 → **0 处差异**（每一年的数值在两份独立文件里逐格一致）

**③ JGAAP 人工层互证**：FY2013 有報 P5 的日本基準 5 年表 vs FY2016 有報 P5 同表重叠年（FY2012/FY2013 共 4 指标）→ **0 处不符**

> 最终状态：①②③ **全部 0 差异**。

## 重要口径注记（踩过的坑）

1. **【△ 是负号】** 日本会计惯例用「△」表示负数（`△1,568,552`、`△ 6,534` 带空格）。漏了这条，成本/费用/亏损会**全部变正**、勾稽全崩。
2. **【列序与中国年报相反】** 日文报表左列＝**前連結会計年度（上年）**、右列＝**当連結会計年度（本年）**。按中国习惯默认"本年在前"会把每一年整体错位一年。
3. **【有報有注記番号列】** 有報行格式为「科目名 [注記番号] 前期 当期」（`売上高 19 1,326,293 1,282,570`）。取前两个数会把注記番号当金额、整行右移一列（实测 その他収益 被读成 `[20, 15789]`）。本库统一**取末两格**。
4. **【表名排在表体之后】** AGC 的 PDF 在 plain 抽文里，表标题出现在该页数字**之后**。"从标题往后切"会整段错开（BS 只切到负债半页、CF 一条切不到）。本库改用**页级归属**：标题在页内任意位置即判定该页归属，无标题页顺延。
5. **【IFRS 移行年混着日本基準的「要約」报表】** FY2013 有報里同时印着**日本基準的要約連結損益計算書**做准则调节。它长得像损益表却是 JGAAP 结构（営業外収益/経常利益/特別損益/少数株主利益）、且**売上原価以正数列示**。误抓会让 FY2012/FY2013 勾稽整段崩溃、并把 JGAAP 的営業利益（70,725）当成 IFRS 的営業利益（79,894）。本库按「日本基準/要約」关键词整页排除。
6. **【分部口径 FY2022 由 4 改 6】** ガラス→建築ガラス+オートモーティブ；化学品→化学品+ライフサイエンス。FY2022 有報**同时列示新旧两套**（旧口径化学品 793,159 = 新口径化学品 655,013 + ライフサイエンス 138,146，精确相等）。**「化学品」在断点两侧不是同一个东西**，直接拉时间序列会得出"化学品收入 2022 年突然掉 17%"的假象。CSV 按 `[旧4分部]`/`[新6分部]` 分组出行。
7. **【分部名不能按表头顺序读】** plain 抽文把分部表头打散（`表計上額ガラス 電子 化学品`）。本库按**格数**定 schema（n = 单元格数 − 3，减去 合計/調整額/連結計上額），再用表头文本逐名验证（全部年份 `_hdr_missing` 为空）。
8. **【nil 必须占位】** 分部行含「－」（如 `179 － 3,141 213 …`）。丢掉 nil 会让后面每列左移一格（建築的数变成オート的数）。三表同理（FY2024 短信「売却目的で保有する資産に含まれる現金…」只有一列有数）。本库用 nil 感知的 `parse_cells`。
9. **【CF 有一行容易漏】** 近年新增「売却目的で保有する資産に含まれる現金及び現金同等物の増減額」，夹在「換算差額」与「増減額」之间（FY2024 −707 / FY2025 +712）。漏掉它，现金流四项和会差 700 上下。
10. **【全角数字】** 早年有報用全角写科目名（`基本的１株当たり`、`１年内返済予定`），不做全角→半角归一会整列静默为空。
11. **【AES 加密 PDF】** 部分年份 有報 为 AES 加密，pypdf 需 `cryptography` 包才能读。本库用**系统 python3**（自带 cryptography）跑提取；`scripts/.venv` 无该包。
12. **【AGC 服务器 HTTP/2 断流】** 大文件走 HTTP/2 会中途 `INTERNAL_ERROR` 断流，且**半截文件仍以 %PDF 开头**——只查文件头会误判成功。下载须 `--http1.1` + 校验尾部 `%%EOF`。
13. **【営業利益 ≠ 一般意义的营业利润】** AGC 的「営業利益」**不含**减值/业务重组/资产处置（这些走その他収益・費用、落在营業利益与**事業利益**之间）。跨公司比较营业利润率时须注意这一口径差。
14. **【CF 印刷舍入】** 现金流四项相加与「増減額」常有 1-3 百万円残差（按千円计算、按百万円列示），逐行核对确认无遗漏科目 → 容差 10。
15. **【FY2025 有報文本层损坏】** 从 EDINET 取到的 FY2025（第101期）有報，**CID 字体映射坏了**——日文全部乱码（`0h}0 0cÐQúfø^0` 之类），数字可读但科目名不可读，概念锚定拿不到任何一行。故 FY2025 改用**決算短信**为解析源（两者三表数值同源、且 FY2025 短信的前期列与 FY2024 有報逐格一致，已在跨源互证中验过）。该有報 PDF 仍归档在 `report/AGC旭硝子/` 备查。
    → 提取层对此有**自动兜底**：同年若已有有報版但解析结果不健康（IS<15 或 BS<25），允许短信版覆盖，避免"用坏文件盖掉好数据"。
