# ⚠️ 外部行业数据（**不是一手申报** · 与 `财务数据/` 主目录严格分层）

> **这个目录里的数字与主目录的性质完全不同，混用会破坏整个库的可信度分层。读任何一张表前先读完本页。**

## 为什么单独放一个目录

`财务数据/` 主目录的铁律是「**唯一真源 = 一手 SEC 申报**」——三表、比率、分部、经营指标、政策补贴，全部可以回溯到某一份 10-K / 10-Q / 8-K 的某一行，并经过勾稽自洽、XBRL 逐格核、跨申报交叉核三重校验。

本目录里的数字**一条都做不到这一点**。它们来自行业数据商（BloombergNEF、Wood Mackenzie）与行业媒体，特征是：

- **方法论不公开**：口径（turnkey / EPC / 电芯 / 系统）、样本、地域权重都不透明
- **常常是二手转述**：我拿到的多为行业媒体对付费报告的报道，不是原始报告本身
- **同一事实不同来源会打架**（本目录已实证一例，见下）
- **无法勾稽**：没有任何内部一致性可以自证

**所以它们的用途只有一个：给一手数据提供「外部参照系」。** 例如「特斯拉单位收入跌 14.9%」这个事实本身来自一手申报，但「这个跌幅是大还是小」必须靠行业价格变化来判断——后者只能从这里来。

## 使用纪律（四条，硬性）

1. **禁止与主目录数字并列进同一张表、同一行、同一个求和。**
2. **引用时必须标来源与发布日期**，格式见 `行业价格与份额.csv` 的来源列。
3. **绝对值不可与特斯拉的派生指标直接比。** 典型错误：拿 `单位经济-储能.csv` 的「单位收入 273.5」去比 BNEF 的「$117/kWh」——前者分子含光伏与 Powerwall、分母只有储能，且特斯拉以美欧市场为主而 BNEF 全球均价被中国拉低。**只有变化率方向可比。**
4. **来源冲突时不裁决**，两条都记、都标来源，在「冲突登记」一节写明。宁可留一个未决项，也不要挑一个看起来顺眼的。

## 来源可信度分层

| 层级 | 本目录用到的 | 说明 |
|---|---|---|
| **A 上市公司自报** | Fluence（FLNC）业绩 | 对手方的一手申报，可信度接近主目录，但**商业模式不同、绝对值不可比**（Fluence 是外购电芯的集成商，特斯拉垂直整合） |
| **B 行业数据商** | BloombergNEF 储能系统成本调查、Wood Mackenzie BESS 集成商榜单 | 方法论不公开；我拿到的是媒体转述 + 数据商官方新闻稿，非原始报告 |
| **C 行业媒体** | Energy-Storage.News、ess-news、pv magazine | 用于价格点位与事件；**每条已逐一核对发布日期**（本库有过搜索引擎把往年旧闻当新闻返回的教训） |
| **✗ 已排除** | 各类 SEO / 厂商博客 | 数字无出处、常与 A/B 层矛盾，一律不采信 |

## 这批数据当初是为回答什么问题而引入的

2026-09-10：判断特斯拉储能板块的「量增价减」是**行业性价格通缩**还是**针对特斯拉的价格战**。
仅靠一手申报无法回答——因为**一家公司的财报里不含对手行为的信息**，这是信息集类型问题，不是数据量问题。
结论与推导见 `../../分析.md` 二③ 与 `../../财报关注要点.md` 的跟踪变量 4/6。

## 维护

- 每次新增行必须填全「来源 / 发布日期 / 可信度层级」三列，缺一不入表。
- 行业数据**不做勾稽校验**（没有可勾稽的内部结构），因此**更要靠来源标注约束**。
- 由 `_build_external.py` 生成，数据以常量形式写在脚本里、逐条带出处注释，改数改脚本。
