### ⚠️ 为什么资产负债表起点是 2008、损益起点是 2005

- 424B4（2010-06-29）的**经审计资产负债表只列 2008-12-31 与 2009-12-31 两个时点**（外加未经审计的 2010-03-31）；同一份文件的 **Selected Financial Data 却把损益回溯到 2005**、现金流量表回溯到 2007。三张表的起点因此不同，是招股书本身的披露边界，不是解析取舍。
- **已穷尽三条路验证 2005–2007 年末资产负债表不可得**（非"只探了一条路"）：
  1. 424B4 全文 —— 仅上述三个时点，Selected Financial Data 的 Balance Sheet Data 一节只给 2010-03-31 的 actual / pro forma / pro forma as adjusted 三栏；
  2. S-1 原始版（2010-01-29）—— 与 424B4 同一披露边界；
  3. FY2010 10-K —— 资产负债表只列 2010 / 2009 两列。
- 但**2006 年末现金余额可间接得到**：424B4 现金流量表 2007 年「期初现金 35,401 千美元」即 2006-12-31 余额（已落 `现金流量表.csv` 2007 列）。

## 三重校验（不通过则不写出 CSV）

由 `_build_from_filings.py` 生成。本次构建结果：**三项全过**。

### ① 三表勾稽自洽（359 条 · 0 不通过）

- **损益**：营收+成本=毛利；经营费用分项和=合计；毛利+经营费用=经营利润；经营利润+利息收入+利息费用+其他=税前；税前+所得税=净利；净利−少数股东损益=归母
- **资产负债**：流动资产分项和=合计；流动+非流动=总资产；流动负债分项和=合计；流动+非流动负债=负债合计；**负债+夹层+权益合计=总资产**；权益分项和=归母权益；归母权益+非控股权益=权益合计；印刷「负债和权益合计」=总资产
- **现金流**：**经营/投资/融资三段各自分项和 = 该段净额**；三段+汇率=现金净变动；期初+净变动=期末；现金流量表净利=利润表净利
- **分部**（35 条 · 0 不通过）：分产品收入和=总营收；汽车分项（销售+监管积分+租赁）和=汽车板块合计；分产品成本和=总成本
- **中期**（54 条 · 0 不通过）：上述损益勾稽 + 现金流分段 + 分部拆分 + **Q1+Q2=H1**

### ② XBRL 逐格独立核对（532 格 · 0 不一致 · 容差 0）

`_xbrl/companyfacts-CIK0001318605.json`（SEC 机读 · 公司自报，一手非第三方聚合）按 **accn 过滤到「该年自己的 10-K」**，与印刷转录轨逐格比对，覆盖三表 35 个核心科目 × 15 年。

> **唯一一处刻意排除**：`权益合计`。FY2016 申报把**夹层的可赎回非控股权益（367,039 千美元）也算进了** `StockholdersEquityIncludingPortionAttributableToNoncontrollingInterest`，与印刷资产负债表口径不符（印刷表里该项在负债与权益之间的夹层，不进权益合计）。本库该行按印刷口径派生（归母+非控股），已由「负债+夹层+权益=总资产」勾稽证真，故不纳入逐格核对。

### ③ 跨申报交叉核（76 处分歧全量登记 → `重述与口径变更.csv`）

每份 10-K 的 2–3 个期间列**全量采集**，同一会计年份因此被 **2–3 份申报独立报过**。按 `(XBRL tag, 维度成员, 会计年份)` 逐行比对本年申报自身值与后续申报比较列，分歧分四类处置：

| 类别 | 处置 | 实例 |
|---|---|---|
| **符号相反**（等绝对值、反符号） | 采后续申报值 | FY2021 有 7 行如此（应收/存货/经营租赁车辆/预付/其他非流动资产/偿还债务/购买数字资产/购建太阳能）——FY2021 那份申报的 SEC 渲染**未对当年列套用 negatedLabel**，印刷表是负数、渲染出来是正数 |
| **本年申报数量级错 10×** | 采后续申报值 | FY2014 两行：`GainLossOnDispositionOfAssets1` 印 141,781（应为 14,178）、`NoncashOrPartNoncashAcquisitionValueOfAssetsAcquired1` 印 2,543,931（应为 254,393）——**filer 自己的 XBRL 标错了小数位**，FY2015/FY2016 两份申报的比较列一致纠正 |
| **重复标注**（同一印刷行被打两个 tag） | 整行剔除 | FY2021 把「购买数字资产 1,500」同时标到 `tsla_PurchaseOfDigitalAssets` 与 `us-gaap_PaymentsToAcquireIntangibleAssets`；剔除后投资段分项和 = 印刷净额 −7,868，分毫不差 |
| **真实重述 / 追溯调整** | **保留本年 as-reported**，登记备查 | ①**拆股追溯**：2020-08-31 的 5:1 与 2022-08-25 的 3:1 使 2019/2021 的每股数据与股数在后续申报里被整体重列；②FY2015 对 FY2014 的资产负债表分类追溯（预付/其他非流动资产/总资产等 12 行）；③营运资金分项的口径微调 |

> **方法论意义**：本库的 XBRL 第二轨核的是「该年自己申报的合计科目」，抓不到 filer 在**某一行**上的错标；**跨申报交叉核**才是抓这类错的那一轨（本次逮出 3 行硬错）。反过来，跨申报核也抓不到"三份申报一致地错"，所以三轨必须并存。

### 运行顺序（有依赖）

```
_harvest_rfiles.py --force        # 年报 R 文件（仅新年报提交后需要）
  → _build_from_filings.py        # 三表 / 比率 / 分部 / 重述登记
  → _build_metrics.py             # 经营指标（产量/交付/储能装机）
  → _build_policy.py              # 政策补贴与积分
  → _build_interim_2026.py        # 中期（含分部拆分）
  → _build_unit_economics_auto.py # 汽车单车经济（依赖 分部营收/经营指标/中期/政策补贴）
  → _build_unit_economics.py      # 储能单位经济（依赖 分部营收/经营指标/中期）
  → _build_backlog.py             # 在手订单与预收（依赖 分部营收/政策补贴）
  → _build_ppe.py                 # 固定资产明细（依赖 资产负债表·跨表核）
  → _build_ceo_awards.py          # CEO 薪酬与里程碑（依赖 利润表/现金流量表/经营指标/单位经济-汽车）
  → _build_geo_rpt.py             # 地区营收 + 关联方交易（依赖 利润表·地区合计跨表核）
_外部行业数据/_build_external.py   # 独立，半年一次，跑前人工复核来源日期
```

## 为什么不用第三方聚合数据

三重校验里已有两条独立的一手轨（印刷渲染表 + XBRL companyfacts），且第三条（跨申报交叉核）本次直接逮出 **3 行 filer 自己的硬错**（FY2014 两处 10× 小数位、FY2021 一处重复标注）与 **7 行渲染符号错**。任何第三方聚合数据都是在这些原始瑕疵之上再加一层加工，用它对账一手没有意义——不一致时仍然只信一手。
