# Disney 财务数据（从一手 SEC 申报解析）

> 本目录 = The Walt Disney Company（NYSE: DIS）的**一手财务数据库**：从一手申报解析的所有客观数字
> （三表 + 比率 + 分部 + 中期 + 重述台账）统一落点。
> 公司分析 → `../分析.md`；监控规格 → `../财报关注要点.md`；事件 → `knowledge/companies/Disney/`（分层不混）。

> **数据血缘**：全部 CSV 数字 = 从 `report/Disney/`（**FY1993–FY2025 全部 10-K + FY2026 Q1-Q3 三份 10-Q**）
> 逐行解析 + 勾稽自洽校验。SEC EDGAR 是唯一真源，**不用任何二手数据源**。
> **单位**：三表与分部表为**百万美元**；⚠️ FY1993–FY1997 印刷口径保留一位小数，本库原样保留。
> **本目录是公司数字的唯一真源**——`分析.md` / `财报关注要点.md` 引用本目录，不复制数字。

## 覆盖范围

**年度序列**：FY1993 – FY2025，共 **33 个财年**。
Disney 财年 = 截至 9 月末 / 10 月初的 52 或 53 周（FY2025 截至 2025-09-27）。

### 为什么起点是 FY1993 而不是上市那年

Disney 1957 年在纽交所上市，**不存在可得的招股说明书**：SEC EDGAR 的电子申报自 1993 年才开始，
更早的纸质申报未数字化。本库已按规则 Step −1 的要求**实证不可得**（见下方底座盘点表），
故起点取 EDGAR 上最早的一份 10-K（FY1993，1993-12-22 申报）。

### 三个 CIK

Disney 在 EDGAR 上横跨**三个申报主体编号**，accession 与 CIK 必须配对，否则 Archives 路径 404：

| CIK | 主体名 | 覆盖 |
|---|---|---|
| 29082 | DISNEY ENTERPRISES INC（1996 年前名 DISNEY WALT CO） | FY1993–FY1995 |
| 1001039 | TWDC Enterprises 18 Corp.（1996-10~2019-03 名 WALT DISNEY CO） | FY1996–FY2018 |
| 1744489 | Walt Disney Co（2018 年为福克斯交易新设的控股主体） | FY2019–FY2025 + FY2026 季报 |

### 两条解析轨

| 轨 | 覆盖 | 载体 | 归一方式 | 脚本 |
|---|---|---|---|---|
| **R 轨** | FY2011–FY2025 | 各年 10-K 的 SEC 渲染报表 `R*.htm` | **按 XBRL tag** 归一（印刷措辞 30 年改过多次，tag 稳） | `_harvest_rfiles.py` |
| **Legacy 轨** | FY1993–FY2010 | 10-K 正文（FY1993-2001 纯 txt、FY2002-2010 HTML） | 按标签正则 + **重叠年倒锁链** | `_parse_legacy.py` |

> FY2009/FY2010 的 10-K 虽有 `FilingSummary.xml`，但其中 Report 没有 `HtmlFileName`
> （SEC 那两年不预渲染 R 文件），故归入 Legacy 轨。

**倒锁链**：R 文件每份带 3 年利润表/现金流、2 年资产负债表，Legacy 各年报同理层层重叠。
构建器从已可信年份出发，用重叠年去核 Legacy 候选表，对得上才采纳它带来的更早年份。
**为什么非这么做不可**：Disney 老 10-K 里「CONSOLIDATED STATEMENTS OF INCOME」这串字出现 6–8 次
（目录、附注、pro forma、分部表、并购对价表都含它），纯靠标签打分挑表**实证会挑错**。

Disney 33 年里的列报变更比多数公司密集。**跨断点直接连线做同比 = 错**。

|---|---|---|---|

| FY1998 | 影视制作支出在**经营↔投资**之间重分类 | 经营现金流、投资现金流 | FY1997 经营现金流 as-reported **7,064**，FY1998 年报重述为 **5,099**（差 1,965，与投资活动同额反向对冲）；见 `重述与口径变更.csv` |
| FY1999 | 分部由 3 个拆为 5 个 | 分部序列 | 分组隔开 |
| FY2001 | 采用 **SOP 00-2**，影视制作支出改列经营活动 | **经营现金流** | FY2000 经营现金流 as-reported **6,434**，FY2001 年报重述为 **3,755**（−42%）。**这是本库现金含量序列最大的一处断点** |
| FY2001 | 分部由 5 个并回 4 个；**双层追踪股**（Disney Common Stock / Internet Group Common Stock）并存 | 分部、EPS | FY2001 净亏损 −158 拆为 Disney 股 −41、互联网集团股 −117 |
| FY2002 | 采用 SFAS 142，商誉不再摊销并从无形资产中单列 | 商誉 / 无形资产占比 | FY2001 及以前商誉含在「无形资产」内（故无形资产占总资产 33–48%） |
| FY2004 | 采用 **FIN 46R**，首次并表欧洲迪士尼与香港迪士尼 | 现金流（带入现金 274）、总资产 | 现金流量表单列「初次并表带入现金」 |
| FY2009 | 采用 **ASC 810**，少数股东权益由夹层移入权益 | 权益结构、「净利润 vs 归母净利」两行的含义 | FY2008 及以前「Net income」**即归母**（少数股东损益在其之上扣除）；FY2009 起「Net income」含少数股东 |
| FY2013 / FY2016 | 互动业务先独立成分部、后并入消费品 | 分部序列 | 分组隔开 |
| FY2017 | 采用 **ASU 2016-18**，现金流量表口径含**受限现金** | 期初/期末现金 | FY2017 期末 **4,064**（含受限）vs 资产负债表货币资金 **4,017**；FY2016 及以前两者相等 |
| FY2019 | 收购二十一世纪福克斯；分部重组为 4 个（含 DTC & International）；现金流量表出现**独立的终止经营段** | 全部序列 | 总资产由 98,598 跃升至 193,984；终止经营现金流 10,974 单列 |

| FY2021 / FY2023 | 分部先并为 2 个板块（DMED/DPEP）、后重组为 3 个（娱乐/体育/体验） | 分部序列 | 分组隔开；FY2022 分部表未单列抵销，本库按倒挤补并标注 |

## 勾稽自洽校验

由 `_build_from_filings.py` 在写出 CSV **之前**执行，**不过不写出**（`--force` 可强制）。
当前状态：**通过 136 / 失败 0 / 数据不全 4**。

每个财年验 4 条：

1. **利润链**（分 era）
   - era A（FY2008 及以前）：税前 + 所得税 + 少数股东损益 + 终止经营 + 会计变更累积影响 = 报表 Net income
   - era B（FY2009 起）：税前 + 所得税 + 终止经营 = Net income（含少数股东）
2. **资产 = 负债 + 权益**
3. **经营 + 投资 + 融资 + 终止经营 + 汇率 = 现金净变动**
4. **期初现金 + 现金净变动 + 初次并表带入现金 = 期末现金**

**分部另有独立闸门**（`_build_segments.py`）：各分部营收之和（含分部间抵销）必须等于同年
`利润表.csv` 的营业收入，差额 > 0.5% 则该年不写出。**33 个财年全部通过。**

### ⚠️ 非 as-reported 的 4 处（如实记录，不掩盖）

「每财年优先取该财年自己那份 10-K 的当年列」是本库口径。以下 4 张表在该年自己那份申报里
未能解析出核心科目，改用**相邻年报的比较列**：

| 财年 | 表 | 实际来源 |
|---|---|---|
| FY1993 | 现金流量表 | FY1994 年报比较列 |
| FY1994 | 现金流量表 | FY1996 年报比较列 |
| FY1995 | 现金流量表 | FY1996 年报比较列 |
| FY2010 | 资产负债表 | FY2011 年报比较列 |

### 脚本

| 文件 | 作用 |
|---|---|
| `_harvest_rfiles.py` | 抓 FY2011-FY2025 10-K 的 SEC 渲染报表，按 XBRL tag 归一 |
| `_parse_legacy.py` | 解析 FY1993-FY2010 的 txt/HTML 10-K，**枚举全部表格**吐候选 |
| `_build_from_filings.py` | 合成三表 + 符号/口径归一 + 勾稽闸门 + 重述台账 |
| `_build_segments.py` | 分部营收/经营利润 + 合计闸门 |
| `_build_ratios.py` | 从三表派生全部比率 |
| `_build_interim_2026.py` | FY2026 三份 10-Q → 中期两表 |

> **中间产物 `_rfiles/` `_rfiles_q/` `_legacy/` 入 git**（合计约 3.6MB 纯文本 JSON，
> 与 `finance/特斯拉/财务数据/_rfiles/` 的既有做法一致）。
> 原因：`report/` 下的一手申报**不入 git**（源档柜约定），若中间产物也不入库，
> 拿到本仓库的人就**无法在不重新下载 33 份 10-K 的前提下复核 CSV 是怎么来的**。
> `_legacy/` 里保留了每张表的**全部候选**（含被否掉的），那正是「为什么选了这张表」的证据链。

## 解析踩过的坑（都已在脚本里固化为注释 + 防御）

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| ① | R 文件空值单元格须占位 `None` | 整行数值左移一列 | 非数值单元格一律补 `None` |
| ② | 行的 XBRL tag 藏在 `onclick="…defref_xxx"` | 按印刷标签归一不稳 | 按 tag 归一 |
| ③ | 部分年度报表多出前导脚注列 | 整行右移 | 统一右对齐到期间数 |
| ④ | `class="fn"` **两种含义**：FY2019+ 是空脚注标记、FY2011 却装**真数据**；脚注还可能是 `[1],[2]` 多引用 | 一刀切丢弃 → 整年数据消失；按 `[n]` 判 → `[1],[2]` 被剥成数字 `12` 插进去 | **按内容判**：空或含 `[` → 丢弃；含数字 → 当数据列 |
| ⑤ | FY2012/FY2013 利润表把 **8 个季度列**与 3 个年度列混排 | 年度值被季度值顶掉 | 读表头 colspan 的「N Months Ended」分组，只取 12 个月列 |
| ⑥ | 老文本申报**多行标签**（长科目名折行） | 只取第二行得到 "Taxes" 这种标签 | 留 `pending` 拼成 `full`，匹配时 label / full 分别试 |
| ⑦ | 标签里含括号（`Cash (used) provided by financing activities`） | 在第一个 `(` 处截断，标签只剩 "Cash" | 分隔符改判为「≥2 空格 + 后接数值」 |
| ⑧ | **点引导线**（`NET INCOME......... $ 299.8`，点后只有一个空格） | 分隔符切在 `$` 之后 | 先把 3 个以上的点归一成空格 |
| ⑨ | **无标签小计**归属歧义（分部表该归子段、现金流表该归大段） | 两种都有真实反例，赌哪个都错 | 两个名字**都给**：`label` 用子段、`full` 用大段 |
| ⑩ | HTML 里标题被 `<FONT>` 拆开 | 靠标题定位找不到表（FY2006-2010 分部表整段消失） | **枚举全部表格**按锚点打分，标题只当加分项 |
| ⑪ | 「Selected Financial Data 五年摘要」也含「Cash provided by operations」 | 被当成现金流量表，且因覆盖 5 年而**压过真报表** | 真报表比较期最多 3 年（BS 2 年），超了即弃 |
| ⑫ | 小计行被**排在前面的明细概念**先吃掉（资本开支正则含 `investments in theme parks`，吃掉了投资活动小计） | 投资活动净额整年为空 | 小计行优先匹配「净额/合计」类概念 |
| ⑬ | 「对不上」≠「解析错」（FY2005 营收 31,944 vs 重述 31,374） | 正确的 as-reported 表被否掉 | 只把**量级级差异**（比值在 0.4–2.5 之外、且绝对值 ≥500）当挑错信号 |
| ⑭ | 净利润行印过 `Net income` / `Net income (loss)` / **`Net (loss) income`**（FY2001 亏损年括号在前） | FY2001 真利润表失去核心科目，被一张 **pro forma 表**（营收 25,256 而非真值 25,269）顶替 | 三种写法全认 |
