# 大V理念知识库 · 结构规范（AI 友好版）

> 本规范定义 `gurus/<slug>/` 的标准结构，目标是**让 AI 高效索引、按需调用大V理念来辅助投资**。
> 拟整合/升级现有 `_模板/`（待确认后合并）。首个落地试点：段永平 `duanyongping`。

---

## 0. 设计第一性原理

AI 在本环境（Claude Code）调用知识库靠的是**「渐进式披露 + 文件系统路由」**，不是向量 RAG：
skill 描述词触发 → 读路由文件 → 沿路由逐层下钻 → 只读需要的那几个文件。

> **唯一硬目标：AI 每次回答只需读 2–3 个小而精的文件，而不是吞下整个大V目录。**

由此推出的准则：①分精度层（浓缩↔原文）；②单一职责 + 可预测命名；③路由/索引先行；
④统一 frontmatter 元数据（可按大V/主题/标的/时间筛）；⑤跨大V同一套 schema（才能横向对比）；⑥结论链接证据（可溯源）。

## 1. 目录结构

```
gurus/
├── INDEX.md                 # 全局路由:中文名/别名→slug + 沉淀状态 + 一句话画像
├── _schema/                 # 本规范 + 各文件模板
├── _topics/                 # 跨大V反向索引:估值.md / 能力圈.md / 卖出纪律.md ...
│                            #   每个主题下列出各大V相关「信条卡片」的链接 → 支撑同题对比
└── <slug>/
    ├── 00-profile.md        # L0 一页纸画像
    ├── 01-principles.md     # L1 理念库:原子化「信条卡片」(核心)
    ├── 02-playbook.md       # L2 方法论:可执行 SOP/checklist
    ├── 03-views/            # L3 对具体标的的观点(时效性强)
    │   ├── _index.md        #     标的→文件 + 立场 + 时间戳
    │   └── <标的>.md
    ├── 04-verdicts.md       # L4 历史判断台账(只增不改·⚠️不用于回算大V胜率,见§3 L4)
    ├── 90-sources/          # L9 证据层:原文蒸馏 + 原始 PDF 指针(溯源才下钻)
    │   ├── _index.md        #     篇/章/主题 → 页码 + 摘要 + 金句
    │   └── <书或专栏>/<篇>.md
    ├── routes.md            # 「给 AI 的地图」:问题类型→读哪层
    └── discipline.md        # 该大V特有的回答纪律(别越界替他发声)
```

**数字前缀 = 精度层级**：越小越浓缩。问理念→`01`；问方法→`02`；问某股→`03`；要溯源→`90`。

## 3. 各层文件规范

### L0 `00-profile.md` — 一页纸画像
字段：一句话定位 · 流派 · 核心信条 3–5 条（链到 01 的卡片）· 能力圈（懂什么/不碰什么）· 明确禁区（不做空/不借钱/不用 margin…）· 标志性口头禅。**读完就能给这位大V定调。**

### L1 `01-principles.md` — 信条卡片（本库核心单元）
把理念拆成一条条独立、同构、可引用可对比可溯源的卡片。**粒度=单条信条**（不要糊成一大块）。模板：

```markdown
### P-01 本分（做对的事 + 把事做对）
- 主张: 只做对的事情,并努力把事情做对;发现不对立即停止(stop doing)
- 理由: <为什么他坚持这条——用他自己的逻辑>
- 适用: 一切投资/经营决策的价值观底座
- 边界/反例: <他承认的例外或踩过的坑,如 GE>
- 关联: [[P-02 平常心]] · [[P-05 stop-doing清单]]
- 出处: [[90-sources/投资问答录/xxx]] p.<页码>
- 强度: 核心信条
- 金句: "<从原文摘的原话,一句>"
```

> ⚠️ **示例里的「理由/金句/页码」是占位**，subagent 必须从**原始 PDF / 已沉淀原文**回填与核验，**不得沿用占位、不得凭训练印象编造段永平没说过的话**（见 §6 铁律）。

### L2 `02-playbook.md` — 方法论 SOP
把可执行的方法抽成 checklist / 步骤。段永平至少含：**毛估估（现金流折现的模糊版）估值法** · **right business + right people + right price 三关** · **stop-doing 清单法** · **买卖决策纪律**（持有就是买入 / 不到便宜不动手 / 看不懂不碰）。每个 SOP：目的→步骤→判据→他举过的实例。

### L3 `03-views/<标的>.md` — 对具体标的的观点
每个标的一文件，按时间列他的判断与理由。段永平重点标的：**苹果 · 茅台 · 网易 · GE · 拼多多**（及 UHAL、万科等如有）。`_index.md` 汇总：标的 → 文件 → 现有立场 → 最近时间戳。

### L4 `04-verdicts.md` — 历史判断台账（轻量、只增不改）
一行一条：`时间 | 标的 | 当时判断 | 当时理由 | 出处`。**刷新其他文件时绝不回改本文件。**

> ⚠️ **本条于 2026-08-06 修正**：旧版写「用于日后回算他（和你自己）的命中率」，与 2026-07-08 确立的铁律冲突，**作废**。
>
> **铁律：不做大V回测 / 胜率复盘 / 大V排行榜**（原 `backtest-call` skill 已删除，**不重建**）。理由四条：
> ① **数据本质二手**——公开发言 ≠ 真实仓位，持仓披露滞后/漏、观点 ≠ 操作、未公开调仓永远补不齐；据此算胜率就是拿二手数据当一手用，违背项目 facts-first 铁律。
> ② **幸存者偏差**——某位大V某段区间跑赢，不代表方法论可复制。
> ③ **大V自己反对被神化**——「永远不要神话任何人·学思考方式而非结论」；回测胜率恰好把大V变成「结论提供者」。
> ④ **会滑向跟单**——回测的下一步几乎必然是「跟着抄」，与本项目「我的客观分析 + 大V只是灵感来源」的定位南辕北辙。
>
> 因此台账里的 ✅/❌/⏳/➖ 是**归纳性痕迹**（留档看观点演化、帮理解其 discipline），**不是预测性数据**——不拿它算胜率、不用它排大V。
> **可以回算胜率的只有「我自己」的判断**，走主观层 `judgments/<公司>/观点变更.md`（append-only），与本层无关。
> 正确用法：把大V视角**当镜子审视自己的分析**，不当结论输出器。

### L9 `90-sources/` — 证据层
`_index.md`：把《投资问答录·投资逻辑篇》按章/主题编目 → 页码 + 3–5 行摘要 + 值得引用的金句。正文文件留**主题摘要 + 页码指针 + 金句节选**（不整段搬全书）。平时 AI 不读，需引用/核验才下钻。

### 路由与纪律
- `routes.md`：`问理念→01 | 问方法→02 | 问某股→03/<标的> | 要历史判断→04 | 要原文出处→90`；并列段永平的触发词（大道无形我有型/本分/能力圈/毛估估/不懂不碰/stop doing/买股票就是买公司…）。
- `discipline.md`：回答口径纪律——只转述他说过/做过的，不替他对新标的发表他没表过态的观点；区分「他明确说过」vs「据其理念推断」。

## 4. AI 调用链路（优化后）

`guru-query 触发 → INDEX 定位 slug → routes.md 导航 → 读对应层(00/01/02 之一,一次读得下) → 需个股则 03 → 需溯源则 90 → discipline 约束口径`。**平均 2–3 个小文件成活。**

---

## 5. ingest 配套（关键）

`ingest-guru`/`ingest-book` 今后要**「入库即结构化蒸馏」**：读原文的同时，直接抽 → 信条卡进 `01`、个股观点进 `03`、判断进 `04`、原文摘要进 `90`，并回写 `_topics`。**不再是先堆 posts 后整理。**

---

## 6. 质量铁律（红线）

1. **只用真实原文**：所有卡片/金句/观点必须来自**原始 PDF 或已沉淀的真实文本**，标注出处页码。**严禁用训练数据里的印象编造大V语录/观点**（呼应 `guru-query` 的「不要从训练数据回答」与项目 facts-first 铁律）。
2. **区分事实与推断**：他明确说过的 = 事实层；由其理念延伸的 = 必须标「据其理念推断」。
3. **入库必 QC**：主理人（我）抽查卡片出处、核对金句原文、排查有无编造，再定稿。
